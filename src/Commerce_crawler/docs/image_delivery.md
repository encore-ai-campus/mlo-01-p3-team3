# 이미지·manifest 전달과 NAS

2026-10-16 기준이다. 수집·다운로드 실행은 [이미지 문서](image_localization.md), 실제 검사 결과는 [검증 기록](validation_results.md)을 따른다.

## 전달할 자료

이미지와 상품의 연결 manifest는 media/products_with_local_images.jsonl이다. 상품 ID·카테고리·원본 URL·역할·순서·파일명·경로·해시·상태를 같은 상품 객체에서 확인한다. 파일 이름만으로 모든 연결 근거를 대신하지 않는다.

| 목적 | 전달할 구성 |
|---|---|
| 상품별 사진 열람·활용 | media/categories/와 media/products_with_local_images.jsonl을 같은 media 루트 아래 유지 |
| 원본 추적·필드 검토 | 위 자료 + 같은 시점 product_raw.jsonl/products.jsonl/run_report.json |
| 다운로드 재개·캐시 재사용 | 위 자료 + media/images/와 image_downloads.jsonl, 별도 공유 캐시를 썼으면 해당 캐시 |

다운로드 도구는 캐시 이력의 실제 경로·해시를 확인한다. categories만 전달받고 원본 캐시를 생략하면 사진 열람은 가능해도 기존 URL의 네트워크 요청 생략이 그대로 보장되지는 않는다.

경로 예시:

```text
media/
  products_with_local_images.jsonl
  categories/1523647/danawa/16272926/danawa_16272926_001_<urlhash>.jpg
  images/<sha256>.jpg
  image_downloads.jsonl
```

JSON의 local_path/category_paths는 media 기준 상대경로다. 파일을 다른 이름으로 바꾸거나 상품별 폴더를 평탄화하면 연결이 깨지므로 그대로 유지한다. `collected_at`과 다운로드 시각은 구분한다. 실패·대기에는 local_path가 null일 수 있으므로 모든 images 원소를 성공 파일로 가정하지 않는다.

## 하드링크의 의미와 주의

하드링크는 같은 파일시스템 안의 여러 경로가 하나의 파일 데이터 객체를 가리키는 구조다. 한 경로를 지워도 다른 링크가 있으면 데이터는 유지되고, 파일 내용을 직접 수정하면 다른 링크에서도 바뀐다. 도구가 경로를 새 파일로 교체하는 경우에는 기존 링크 관계와 분리될 수 있다.

현재 저장 코드는 링크 생성을 시도한 뒤 실패하면 복사한다. 따라서 categories 경로가 존재한다는 사실만으로 중복 용량이 없다고 단정하지 않는다. 일반 탐색기·WebDAV 복사나 받는 도구가 링크를 보존하지 않으면 독립 파일이 될 수 있다.

2026-10-16 검사에서 로컬 1,426개 경로는 이미지 데이터 객체 654개를 공유했다. NAS 5쌍은 클라이언트 파일 ID가 달랐고, Z: 경유 생성은 WinError 87로 실패했다. Z:는 RaiDrive WebDAV이므로 NAS 내부 파일시스템이 링크를 지원하지 않는다고 확정한 결과는 아니다. NAS 내부 실행은 아직 검증하지 않았다.

## 전달 후 검사

1. 원본·가공·manifest의 source/product_id/job_id와 연결 해시를 대조한다.
2. downloaded 항목의 상대경로가 전달 루트 안에 있고 파일이 존재하는지 확인한다.
3. SHA256·bytes·해상도·형식을 실제 파일과 대조한다.
4. 상품별 카테고리 소속과 category_paths·파일명 식별자를 대조한다.
5. URL 연결 수·성공/실패 수·고유 해시 수·실제 파일 경로 수를 각각 집계한다.

이미지 무결성 검사는 validation.verify_assets로 실행할 수 있으나 결과 보고서를 전달 경로에 쓴다. 읽기 전용 감사가 필요하면 image_errors를 읽기 검사로 사용하거나 별도 로컬 보고 경로를 준비한다. 현재 NAS 파일을 검증했다는 결과를 다른 복사본에 자동 적용하지 않는다.

## 링크 보존·재구성은 별도 작업

하드링크 지원 tar로 **링크가 살아 있는 원본 media 전체**를 묶고 지원되는 NAS 내부에서 풀거나, 같은 전송 묶음에 images와 categories를 포함해 rsync -H로 관계를 보존하는 방안을 사용할 수 있다. 수신 파일시스템·권한·도구 지원을 먼저 작은 표본으로 검증한다. 현재 수집기의 전달 기능으로 구현한 것은 아니다.

이미 분리된 복사본을 재구성하려면 manifest와 실제 해시를 대조하고, 임시 링크 생성 성공 후 해당 카테고리 복사본을 교체해야 한다. 파일을 먼저 삭제하거나 이름만 보고 합치지 않는다. 하드링크 재구성 자동 도구는 현재 없다.

## 용량 안내

664장 표본 평균 38.16KB, 상품당 관측 평균 2.26장으로 65,498개 상품 이미지 한 벌을 약 5.65GB로 추정했다. 여유를 더한 계획치는 약 7GB다. 모두 4장이면 약 10GB이고 실제 코드는 4장보다 많은 갤러리도 보존한다.

7GB는 JSON·상세 HTML·체크포인트·캐시/카테고리 독립 복사본을 합한 전체 배치 예산이 아니다. 두 폴더를 NAS에 독립 파일로 저장한다면 추가 용량을 산정한다. [계산 조건과 표](validation_results.md#하드링크와-저장-공간)
