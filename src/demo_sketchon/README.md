## 직접 상품 추천 통합 MVP (2026-10-16)

같은 Django 서버의 **`/interior-recommand/`**에서 회원·비회원 모두 사진+설명/스케치로 상품을 직접 추천받는다. Home→‘내 공간 꾸미기’의 기존 그림판에서 사진·스케치·요청사항을 입력하고 ‘상품 추천받기’를 누른다. 추천 화면은 전달된 입력과 결과만 표시하며 별도 입력 폼을 두지 않는다. run 없이 추천 경로를 열면 기존 편집기로 이동한다. 화면 표시명·로고·색상은 SketchOn을 사용한다. 기존 모의 공간 만들기는 펼침 메뉴에서, 회원·저장·찜·Raw 수집은 기존 경로에서 유지하며, 아래 기존 모의 생성 설명과 직접 추천을 구분한다.

추천은 `interior_recommender/sample/crawl_test/full/catalog-with-links/products.json`의 기존 295개 로컬 상품과 완료 벡터를 재사용한다. 입력 해석·질의 임베딩은 기존 Gemini 설정을 사용한다. 별도 `interior_recommender.web` 서버·추천용 DB·MySQL·Kafka·FAISS는 필요하지 않다. 기존 로그인·세션·Canvas와 신규 추천 작업 원장은 로컬 SQLite를 사용한다.

**현재 저장소 경로의 설치·실행, 환경 변수, API·권한과 검증은 [직접 추천 통합 실행 안내](docs/ver2/직접추천_통합_실행.md)를 따른다.** 아래 `C:\mlo-01-p3-team3` 경로는 이전 데모 환경의 기록이다.

확정 로고는 검정 영문 한 줄 **Sketch · On**과 점을 찍는 기하학적 연필입니다. 선택한 이미지 원본은 `sketch/static/sketch/assets/sketchon-logo-approved.png`에 저장했으며 세 화면과 기존 푸터는 공통 `brand.html`로 표시합니다.

최초 구현부터 8차 수정까지의 변경 이유와 비회원 식별 정책 검토 사항은 [데모 변경 이력](docs/ver2/데모_변경이력.md)에 정리했습니다.

현재 UI는 `roompick_ver0.2`를 참고한 흰 배경·녹색 포인트·여백·얇은 테두리를 사용하며, 로고는 확정한 검정 영문 Sketch · On으로 통일했습니다. 세 화면은 `sketch/static/sketch/roompick-ui.css` 한 파일을 사용합니다. PC는 그림판 옆 설명 패널, 결과 옆 물체 패널을 배치하며 모바일은 입력 탭과 하단 생성 버튼을 사용합니다. 기존 도구·직접 가구 이동·상품 세 칸과 데이터 처리는 유지합니다. 스타일 URL에 버전을 붙여 이전 디자인 캐시와 섞이지 않도록 했습니다.

현재는 **비회원 체험과 자체 회원 계정·개인 이력**을 함께 제공합니다. 아이디·비밀번호·닉네임으로 가입하고 프로젝트 버전 저장·수정·이미지 비교와 상품 찜을 사용할 수 있습니다. 비회원은 서버 IP별 한국 시간 매일 3회 성공 생성까지, 회원은 생성 제한 없이 이용합니다. 다운로드는 제한하지 않습니다. Home에서 새 작업을 시작하고 검색하면 별도의 결과 페이지로 이동합니다. 익명 방문 ID는 같은 브라우저의 세션 쿠키가 유지되는 동안 같습니다. 다른 브라우저·기기에는 다른 ID를 부여합니다. 사진과 행동 기록은 서버에 남으며 검색 결과의 PNG를 내려받을 수 있습니다. 작업 JSON은 내부 조회 API로 보관합니다.

## PowerShell 실행

```powershell
Set-Location C:\mlo-01-p3-team3\src\demo_sketchon
python -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8003
```

Python과 Pillow가 설치된 환경이 필요합니다. 기존 검증 환경은 Python 3.14.6이며 의존성 범위는 `requirements.txt`를 따릅니다. 이동해 온 `.venv`가 실행되지 않거나 다른 PC에서 시작할 때는 위 명령으로 해당 위치에 가상환경을 구성합니다. `python`을 찾지 못하면 설치된 Python 실행 파일 경로 또는 `py -3`을 사용하세요. 이동 전에 실행한 서버는 종료한 뒤 새 경로에서 다시 실행해야 합니다.

PC에서 <http://127.0.0.1:8003>에 접속합니다. 가상환경을 활성화하지 않아도 위 명령을 그대로 실행할 수 있습니다. 기존 게임 서버·광고 서버·MySQL·Kafka·Spark 실행은 필요하지 않습니다.

## 팀원과 내부망에서 접속

개발 PC의 내부망 공유 설정 주소는 **192.168.0.44**입니다. 실행 시 `ipconfig`로 IPv4를 확인하고, 같은 주소라면 팀원은 **http://192.168.0.44:8003/** 에 접속합니다. 같은 내부망에 있어야 하며 새 프로젝트 경로에서 개발 서버가 실행 중이어야 합니다.

```powershell
Set-Location C:\mlo-01-p3-team3\src\demo_sketchon
.\.venv\Scripts\python.exe manage.py runserver 0.0.0.0:8003
```

settings.py의 기본 ALLOWED_HOSTS에 현재 IP를 추가했습니다. 0.0.0.0은 서버의 수신 설정이며 브라우저에는 실제 PC 주소를 입력합니다. PC에서는 기존 http://127.0.0.1:8003/ 주소도 사용할 수 있습니다.

기존 개발 PC의 Wi-Fi 공용 네트워크와 Python TCP 수신 차단 규칙에 맞춘 방화벽 스크립트를 포함합니다. 관리자 PowerShell에서 아래 파일을 한 번 실행하면 192.168.0.44의 TCP 8003 포트를 같은 서브넷(192.168.0.0/24)에만 허용하도록 설정합니다. 기존 Python TCP 차단 규칙에서는 해당 포트만 제외하며 다른 포트와 UDP 차단은 유지합니다.

```powershell
& C:\mlo-01-p3-team3\src\demo_sketchon\Allow-RoomPick-LAN.ps1
```

방화벽 스크립트의 IP·서브넷·Python 실행 파일 경로는 기존 개발 PC 기준이므로 다른 PC에서는 해당 값을 먼저 확인합니다. IP는 DHCP로 바뀔 수 있습니다. 그때는 ipconfig로 주소를 확인하고 ROOMPICK_HOSTS 환경 변수 또는 settings.py의 허용 주소와 방화벽 파일의 주소를 갱신해야 합니다. 서로 다른 Wi-Fi/VLAN이나 AP의 기기 간 통신 차단 여부는 별도 네트워크 설정에 따릅니다. 실제 다른 팀원 PC에서의 접속 성공은 직접 확인해야 합니다.

## 현재 데모 흐름

1. Home의 **내 공간 꾸미기**를 누릅니다. 인테리어 예시와 이용 순서를 안내합니다.
2. 중앙 사진 선택·예시 공간 체험 또는 파일 드래그 앤 드롭으로 시작합니다. 같은 버튼 한 쌍을 업로드 후에는 그림판 제목 옆에서 사용해 사진을 교체합니다. 중복 버튼과 카메라 촬영은 제공하지 않습니다.
3. 이미지 위쪽의 기존 도구로 원하는 위치에 표시하거나, 별도 설명(1,000자 이내)만 입력합니다. 대표 스타일은 최대 한 개 선택합니다. 사진과 스케치 또는 설명이 필요하며, 생성 전에는 가구 품목 선택을 요구하지 않습니다.
4. **공간 만들기**를 누르면 모든 획·텍스트·도형·채우기와 설명을 **하나의 상품 입력**으로 묶고 결과 가구 한 개를 배치한 뒤 **별도의 예측 결과 페이지**로 이동합니다. 완료된 작업은 서버에서도 잠겨 추가 스케치·문서 저장·새 생성을 거부합니다.
5. 결과 위쪽에 **[익명 방문 ID 앞 8자리] 님이 원하시는 “품목”을 생성하였습니다.**를 표시합니다. 결과 페이지에는 사진 업로드·스케치 도구가 없습니다.
6. 합성된 가구를 바로 눌러 이동·모서리 크기 조절할 수 있습니다. 가구 조작이 끝날 때 합성 PNG와 배치 좌표를 갱신합니다. 배치 실행 취소·다시 실행·처음 배치로와 원본 사진 비교도 지원합니다. 저장 실패 시 마지막 저장 위치로 돌아가고 이력은 보존합니다. 결과 물체를 선택하고 **선택한 물체의 상품 찾기**를 누르면 기존 이미지 세 칸에 모의 상품을 표시합니다. **품목·가구 배치 수정** 토글도 실제 가구를 선택하며 가로·세로 크기(사진 대비 %) 입력을 마치면 이미지와 이력에 자동 저장합니다. 이동·크기 변경은 합성 이미지와 실제 배치를, 품목 변경은 추천 조건을 수정하며 품목 변경 전에는 검색 품목 적용 버튼이 비활성입니다.
7. 배치 기록 아래 **이미지 내려받기**는 마지막 저장 배치의 PNG를 제공합니다. 개발자 확인용 작업 JSON 다운로드 버튼은 사용자 화면에서 제거했으며 내부 데이터 저장과 조회 API는 유지합니다. 같은 배치 기록 아래에 세 가지 재시작 버튼도 모았습니다. 편집·결과 사진은 같은 표시폭·비율을 사용하고 합성 PNG는 편집 사진과 같은 픽셀 크기입니다.
8. **처음부터 다시 그리기**는 같은 사진의 빈 스케치·설명·스타일, **스케치 수정하기**는 같은 사진에 생성 직전 스케치·설명·스타일 복원, **다른 상품 검색하기**는 사진 업로드 전 새 작업으로 이동합니다. 방문 ID는 유지하고 작업 ID만 새로 생성합니다. Undo/Redo 기록은 새로 시작하며 원래 결과는 보존합니다.

**실제 AI 인식·쇼핑 검색·사진 속 기존 가구 판별을 수행하지 않습니다.** 전체 텍스트의 단어 규칙으로 샘플 가구를 선택하고 알 수 없는 입력에는 예시 소파를 사용합니다. 전체 스케치를 한 영역·한 상품으로 처리하며 새 소파 결과에는 선택한 스타일의 예시 이미지를 사용합니다. JSON의 mode=mock, basis와 classification_basis로 모의 처리임을 표시합니다. 추천 카드는 실제 가격·판매 링크를 제공하지 않습니다. 기존 결과의 샘플 price 필드는 호환을 위해 유지합니다.

## 편집 기능

- 마우스·손가락·터치펜 공통 Pointer Events 입력. 그림판에서만 touch-action: none을 적용하고 다른 영역은 스크롤할 수 있습니다.
- 펜·지우개·색상·크기 설정. 펜과 지우개의 크기를 별도로 기억하고 실제 화면 크기의 원형 커서를 보여줍니다. 손가락 입력에서는 접촉 중 표시됩니다.
- 별도 선택 버튼 없이 **영역 선택**으로 요소 클릭·이동과 빈 곳부터 드래그 영역 선택을 함께 수행합니다. 지우개는 크기, 채우기는 색상, 텍스트 입력은 색상·글자 크기만 표시합니다. 영역 선택에서 텍스트를 고르면 색상을 표시하며 변경을 기존 글자와 실행 취소에 반영합니다. 글자 크기는 텍스트를 더블클릭해 입력 상태에서 조절합니다.
- 사진 표시폭은 **100%**, 높이는 사진 비율로 정합니다. 6차의 노트북 사진 크기 제한은 제거했습니다. 편집·합성 해상도와 업로드 원본 보관 정책은 유지합니다.
- 지우개는 펜·도형·채우기·텍스트에서 지나간 자리만 지웁니다. 지운 경로도 요소에 연결되어 이동·크기 조절·복사·실행 취소와 함께 처리됩니다. 공간 사진은 지우지 않습니다.
- **T 텍스트 → I 모양 커서로 사진 위치 클릭 → 사진 위에서 직접 타이핑**합니다. Enter 또는 바깥 클릭으로 완료하고 Shift+Enter는 줄바꿈, Escape는 입력 취소입니다. 한글 IME 조합 중 Enter는 완료로 처리하지 않습니다. 삽입 후 텍스트는 바로 이동할 수 있으며 더블클릭하거나 텍스트 도구로 다시 눌러 수정합니다.
- 사각형·타원·직선·화살표는 드래그로 삽입합니다.
- **사진 자르기**: 남길 영역을 드래그하고 적용합니다. 현재 스케치가 있으면 비워진다는 확인을 표시합니다. 자르기는 같은 방문 ID의 새 작업을 생성하며 기존 스케치를 새 사진 좌표로 변환하지 않습니다.
- **채우기**: 스케치 레이어의 연결된 픽셀 영역만 채웁니다. 사각형 안쪽·분리선 한쪽·내부 타원처럼 닫힌 경계를 구분합니다. 열린 선에 틈이 있으면 색이 이어진 영역으로 퍼질 수 있습니다. 사진 픽셀 자체는 채우기 경계로 사용하지 않습니다.
- 도형의 **외곽선**을 눌러 이동·크기 조절합니다. 빈 내부는 선택되지 않아 다른 도형을 넣을 수 있습니다. 채운 부분을 클릭해도 원래 도형 또는 펜 윤곽과 함께 선택됩니다. 바깥 도형은 자신의 채우기만 함께 움직이고 내부에 따로 넣은 획·도형·분리선은 이동하지 않습니다. 펜 획끼리 겹치거나 닿으면 자동 연결됩니다.
- **영역 선택 → 전체를 둘러싸도록 드래그 → 그룹화**하면 떨어진 획과 도형도 함께 조절할 수 있습니다. 선택한 그룹은 그룹 해제로 분리합니다.
- 요소를 선택한 상태에서 선 크기를 바꾸면 선택한 펜·도형의 실제 선 두께가 바뀝니다. 그룹은 해당 그룹의 선을 함께 바꿉니다. 슬라이더 조절 한 번은 실행 취소 한 번입니다.
- 도구 목록 위의 **실행 취소 / 다시 실행** 버튼과 Ctrl+Z/Y가 사진 업로드·사진 교체·자르기·그림·텍스트·도형·채우기·지우기·그룹·선 두께를 작업 순서대로 처리합니다. 첫 사진 업로드 직후부터 실행 취소가 활성화되고, 취소하면 사진 업로드 전으로, 다시 실행하면 같은 사진으로 돌아갑니다. 취소 뒤 새 편집은 기존 다시 실행 기록을 비웁니다. 최근 20단계와 현재 스케치를 같은 탭의 sessionStorage에 보관하며 같은 작업 URL의 새로고침 후 복원합니다. 탭 종료·저장 공간 차단/부족 시에는 복구를 보장하지 않습니다.
- 도형 생성 한 번은 실행 취소 한 번에 대응합니다. 큰 선택 영역의 오른쪽 아래 손잡이 또는 **크기 조절** 버튼을 사용합니다. 자유 그림 획의 이동은 선택 도구를 사용합니다.
- Ctrl/Cmd+C·V 또는 **복사·붙여넣기** 버튼은 선택한 요소와 연결된 채우기·자동 연결 획·명시적 그룹을 함께 복제합니다. 복사 버퍼는 현재 그림판 페이지 안에서 사용하며 OS·다른 앱 클립보드 연동은 없습니다. 텍스트 입력 중에는 기본 텍스트 복사를 유지합니다.
- 선택 요소 삭제, 표시 전체 삭제, 최근 20번 실행 취소·다시 실행. Ctrl/Cmd+Z, Ctrl/Cmd+Y, Shift+Ctrl/Cmd+Z 지원. 선택 요소는 방향키로 이동하고 Delete로 삭제할 수 있습니다.
- 사진 기준 0~1 상대 좌표로 입력·크기를 저장합니다. PC·모바일 화면 크기 변경 시 같은 위치에 다시 그립니다.
- 두 번째 포인터는 무시합니다. 입력 취소·포인터 캡처 상실 시 진행 중인 조작을 되돌립니다.
- 사진은 최대 10MB / 2,500만 픽셀의 JPG·PNG·WebP를 허용합니다. 서버에서 내용을 검증하고 EXIF 회전을 반영한 뒤 최대 2048픽셀 JPEG로 변환합니다. 10MB를 초과하면 안내창이 뜹니다. 일부 휴대폰의 JPG가 MPO(여러 이미지를 포함한 JPEG)로 인식되는 경우에도 첫 번째 사진을 사용해 업로드합니다. 파일 용량·해상도·형식 오류는 각각 구분해 안내합니다. HEIC는 먼저 변환해서 사용합니다.
- 작업 제목은 **나의 공간 스케치**로 고정되어 있으며 오른쪽의 획·표시 개수만 갱신합니다.
- 결과 사진·배치 조작 영역 아래 상품 이미지 카드 3칸에 모의 추천을 표시합니다. 실제 화면에 들어온 카드 노출과 선택·비선호 반응을 추천 실행/항목 ID에 연결합니다. 판매 사이트 연결은 아직 비활성입니다.
- 설명·스타일도 사진 업로드·자르기·스케치와 같은 실행 취소 기록에 포함합니다. 사진 교체·자르기는 작성 중 설명과 스타일을 유지합니다. 모바일은 사진·스케치 / 설명·스타일 탭과 하단 고정 공간 만들기 버튼을 제공합니다.
- 결과 페이지의 가구는 마우스·터치로 바로 선택·이동합니다. 크기는 모서리 손잡이·Shift+방향키 또는 품목·가구 배치 수정의 가로·세로(%) 입력으로 조절합니다. 다운로드에는 결과 가구의 최종 배치가 반영됩니다.
- 두 손가락 확대·이동은 현재 없습니다. 로그인·회원 저장 이력 화면은 8차에서 추가했습니다. 현재 결과 URL을 새로고침하면 해당 결과를 유지하며 빈 스케치로 돌아가려면 다시 그리기를 누릅니다. 현재 탭에 임시 보관된 편집과 통합 기록은 같은 작업 URL의 새로고침 후 복원하지만, 임시 편집 이력과 별도로 회원은 결과에서 프로젝트 버전을 서버에 저장할 수 있습니다.

## 익명 행동 데이터

방문자는 무작위 UUID로 구분하고 같은 브라우저 세션 쿠키가 유지되는 동안 같은 ID를 사용합니다. **자르기·재시작·새 사진 시작·새로고침·Home 이동은 방문 ID를 바꾸지 않습니다.** 작업 ID가 바뀌어도 방문 ID는 유지됩니다. 다른 기기·브라우저·쿠키 삭제·만료 시에는 기존 방문자를 연결하지 못합니다. 기본 유효기간은 1년이며 쿠키 이름은 roompick_sessionid, roompick_csrftoken입니다. 정식 식별·보관·계정 연결 정책은 변경 이력 문서에 별도 설계 과제로 남겼습니다.

Home·편집·결과 접속, 사진 선택/드롭/업로드/자르기, 획 완료/취소, 도구·색상·크기 변경, 텍스트·도형 조작, 채우기, 영역 선택·그룹화·그룹 해제·사진 복귀, 복사·붙여넣기, 실행 취소·다시 실행, 검색 클릭/완료, 결과 가구 조절·저장·다운로드, 세 가지 재시작과 버튼 클릭을 수집합니다. 편집·결과 화면은 같은 전송 큐와 이벤트 UUID 중복 제거를 사용합니다. 새 그림에는 사용자가 고른 가구 카테고리를 넣지 않습니다.

획은 점별 x·y·필압과 함께 묶어 기록합니다. 버튼 클릭 등은 최대 약 1.5초 간격으로 전송하고 검색하지 않아도 수집됩니다. 필압은 수집만 하고 선 두께는 선택값을 사용합니다. event_time은 서버 수신 시각, payload.client_time은 클라이언트 동작 시각입니다.

이벤트 UUID로 중복을 제거합니다. 미전송 기록은 localStorage의 이벤트별 키로 보관하여 여러 탭이 같은 배열을 덮어쓰지 않도록 처리합니다. 연결 복구 시 재전송하고 일반 행동은 페이지 종료 시 sendBeacon을 시도합니다. 영구 거절된 이벤트는 별도로 보관해 이후 전송을 막지 않습니다. 설명·스타일 변경, 사진 비교, 상품 노출·선택·비선호, 검색 조건 수정도 수집합니다. 저장 공간 차단·쿠키 삭제·강제 종료·장시간 오프라인에서는 완전한 전달을 보장하지 않습니다.

작업·사진·합성 PNG·결과 JSON은 세션의 방문 ID로 접근을 제한합니다. 변경 요청에는 Django CSRF 검증을 적용하고 입력 구조·크기·좌표를 검사합니다. 결과는 생성 시점의 문서를 별도로 보관하므로 이후 편집 내용으로 덮어써지지 않습니다. 기존 데모 기록과 DB는 유지합니다.

## 3차 스케치 원본 수집 확장

기존 화면 기능과 행동 이벤트를 유지하면서 초기 화면 시작 클릭과 별도 스케치 원본 수집을 연결했습니다. 원본은 IndexedDB에 임시 보관하고 검색 성공·작업 변경·페이지 종료 시 `data/sketch_raw/<sample_id>.json`에 제출합니다. 별도 Submit 버튼은 없습니다. 펜·지우개의 필터링 전 좌표·시간·종료 상태와 편집 변경분을 보존하며, 자유 스케치의 라벨은 미검수 상태입니다.

결과 화면의 버튼 클릭·이미지 이동·크기 조절·다운로드 기록은 기존 수집을 유지합니다. 원본 전송 실패는 편집·검색을 막지 않습니다. 원본 수집 한도에 도달하면 마지막 기록 상태를 저장하고 이후 미수집을 안내합니다. 작성 중 초안의 자동 복구는 Web Locks가 가능한 localhost/HTTPS에서 지원하며, 일반 LAN HTTP에서는 초안을 보관하고 확정한 outbox의 전송만 재시도합니다.

화면 기능은 [3차 페이지 기능구현리스트](docs/ver2/페이지_기능구현리스트.md), 기존 기준과 확장 내용·조회 명령·미확정 운영 정책은 [3차 행동데이터 수집기준](docs/ver2/행동데이터_수집기준.md)을 참고하세요. 데이터 폴더는 첫 제출 시 생성되며 Git 제외 대상입니다. 동의·보관·삭제·학습 라벨 정책과 학습 전처리는 후속 범위입니다.

## 검증

2026-10-15 기존 경로에서 7차 기능과 확정 로고를 검증했습니다. Django 67개, Node 26개와 실제 서버의 PC/모바일 흐름을 확인한 기록이며 새 경로에서의 실행 검증을 뜻하지 않습니다. 작은 동시성 회귀 검사는 이벤트 16개 병렬 저장, 동일 ID 추천 8회, 동일 버전 배치 8회에서 500 없이 동작하고 배치 저장은 한 번만 성공함을 확인합니다. 운영 처리량을 보장하는 부하 시험은 아닙니다.

신규 업로드부터 원본 바이트와 SHA-256을 파생 JPEG와 따로 보관합니다. 기존 업로드의 원본은 복원할 수 없습니다. 기존 결과의 최초 배치 기준은 migration 시점의 배치이며, 신규 결과부터 생성 순간의 배치를 고정 보관합니다. 결과/품목/추천 기록은 migration 0004~0006으로 기존 DB에 추가합니다.

SQLite는 timeout 20초와 IMMEDIATE 트랜잭션, 배치 버전 조건부 갱신을 사용합니다. 추천 실행은 작업 ID·입력 해시·임대 만료·토큰으로 중복 실행과 늦은 응답을 방어하며 제공자 호출은 DB 트랜잭션 밖에서 수행합니다. 실제 광고 API는 `ROOMPICK_RECOMMENDATION_PROVIDER` 어댑터로 교체하는 구조이며 현재 제공자는 모의입니다.

~~~powershell
Set-Location C:\mlo-01-p3-team3\src\demo_sketchon
.\.venv\Scripts\python.exe manage.py test
.\.venv\Scripts\python.exe manage.py check
node --test tests/geometry.test.mjs
node --test tests/paint.test.mjs
node --test tests/collector.test.mjs
node --test tests/durable-queue.test.mjs tests/platform-api.test.mjs
~~~

격리된 브라우저 검증 서버 예시(별도 PowerShell):

```powershell
Set-Location C:\mlo-01-p3-team3\src\demo_sketchon
$env:ROOMPICK_DB_PATH = "$PWD\test-results\extension\db.sqlite3"
$env:ROOMPICK_MEDIA_ROOT = "$PWD\test-results\extension\media"
$env:ROOMPICK_RAW_ROOT = "$PWD\test-results\extension\raw"
New-Item -ItemType Directory -Force "$PWD\test-results\extension" | Out-Null
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py runserver 127.0.0.1:8015
```

테스트를 실행할 별도 PowerShell도 `C:\mlo-01-p3-team3\src\demo_sketchon`으로 이동한 뒤 `$env:ROOMPICK_TEST_URL = 'http://127.0.0.1:8015'`를 설정하고 `node tests/extension-browser.cjs`, `node tests/concurrency-browser.cjs`를 실행합니다. 결과 화면의 오류 응답·늦은 응답 검증은 `node tests/result-extension-browser.cjs`로 API를 격리해 검사합니다. 일반 서비스 재실행에는 위 테스트 저장소 환경 변수가 없는 새 PowerShell을 사용하세요.

`node tests/ui-layout-browser.cjs`는 PC·모바일 Home/편집/결과 레이아웃, 가로 넘침, 첫 사진 선택 버튼, 도구 노출과 생성·추천을 확인하고 `test-results/ui/`에 화면 캡처를 저장합니다.

`node tests/revision7-browser.cjs`는 전체폭 사진·중복 버튼 제거·도구별 설정·선택한 글자 색상 변경 및 undo/redo·실제 가구 수정·품목 변경 여부·사진과 합성 해상도 일치를 PC/모바일에서 확인합니다.

선택적 실제 브라우저 테스트는 Playwright가 있는 환경에서 서버 실행 후 node tests/browser-check.cjs로 수행합니다. 기본 브라우저는 Edge입니다. 스크립트별 기본 포트가 다르므로 격리 서버를 사용할 때는 `$env:ROOMPICK_TEST_URL = 'http://127.0.0.1:8015'`를 명시하세요. 브라우저를 선택할 수 있는 스크립트에서는 `ROOMPICK_TEST_BROWSER`를 사용합니다. 테스트 캡처는 test-results/에 저장합니다. Playwright는 서비스 실행 의존성이 아닙니다.

원본 수집의 전송 실패·재전송·복제 탭 보호는 `node tests/collection-browser-check.cjs`로 확인합니다. 브라우저 테스트는 사진·작업·원본을 생성하므로 실제 DB 대신 별도 테스트 저장소와 서버를 사용하세요.

기존 게임 서버의 JSON 이벤트·트랜잭션·버전·내보내기 구조와 게임 클라이언트의 CSRF·응답 검증 방식을 참고했습니다. 실제 상품·AI 연결, 광고 서버 연동, Kafka/Spark, 로그인 이력, 공개 서비스 배포는 후속 범위입니다. 현재 SQLite와 Django 개발 서버는 로컬 검증용입니다.



## 8차 회원·생성 제한·개인 기록

- 전 페이지 오른쪽 상단 로그인/로그아웃. 로그인 입력란은 ‘아이디’, 가입 입력란은 ‘아이디·닉네임’으로 표시합니다. 가입 성공 시 “가입이 완료되었습니다!” 안내창을 한 번 띄우고 자동 로그인 상태로 시작합니다. 새로고침·뒤로가기에는 안내를 반복하지 않습니다. My는 회원정보·인테리어 찜 목록·프로젝트 내역으로 구성합니다. 닉네임과 비밀번호를 변경할 수 있고 비밀번호 변경 후 로그인은 유지합니다.
- 로그인할 때 현재 브라우저의 미귀속 작업만 계정에 연결합니다. 기존 owner·Raw.writer_id는 유지하며 다른 회원 기록을 가져오지 않습니다. 편집의 로그인 링크는 스케치·텍스트·설명·스타일을 먼저 저장합니다.
- 비회원은 서버 REMOTE_ADDR별 KST 하루 3회입니다. 같은 Wi-Fi/NAT에서는 횟수를 공유할 수 있습니다. 실패·같은 request_id 재전송·다운로드·배치 조절·추천은 차감하지 않습니다.
- 회원 결과의 ‘프로젝트에 저장’은 독립 PNG와 입력·배치 snapshot을 보관합니다. 저장 버전에서 수정·재생성하면 같은 프로젝트의 새 버전이 생깁니다. 본인 저장 이미지 두 장을 비교할 수 있습니다.
- 상품 찜은 기존 좋아요/비선호와 독립이며 My 목록에서 해제합니다. 실제 사양 비교는 다음 단계입니다.
- 광고는 편집·결과·My 본문과 분리된 오른쪽 전용 열의 300×600px 배너 자리입니다. 본문을 왼쪽으로 배치하고 Home·로그인·회원가입에는 광고를 표시하지 않습니다. 1280px 미만 화면에서는 배너를 숨겨 편집 공간을 유지합니다. 실제 광고·무작위 노출·개인화는 연결하지 않았습니다.
- migration 0007과 Django auth migration을 적용해야 합니다. 기존 데이터는 자동 회원 귀속하지 않습니다. 최초 로그인 시 현재 브라우저의 미귀속 작업만 연결합니다.
