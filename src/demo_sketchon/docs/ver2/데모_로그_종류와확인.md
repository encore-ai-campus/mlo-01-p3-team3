| 구분 | 무엇을 말하는가 | 저장 위치 | 확인할 질문 |

Raw와 업무 테이블까지 넓게 원천 기록이라 부를 수 있지만, 전부 서버 stdout에 출력되는 것은 아니다. `POST /events/ 200` 한 줄에 좌표 전체가 담기지 않으며, 서버 로그 파일을 보는 것만으로 모든 사용자 행동을 복원할 수 없다.

## 2. SketchEvent의 공통 구조

| 필드 | 의미 |
| --- | --- |
| event_id | 개별 사건 UUID·중복 제출 기준 |
| project_id | 사건이 연결된 Project |
| event_type | 기능·성공 사건의 종류 |
| event_time | 서버가 저장한 시간; USE_TZ에 따라 UTC로 출력될 수 있음 |
| payload | 사건별 버튼·요소·좌표·결과·추천 ID 등 |
| payload.client_time | 일반 브라우저 수집기가 붙이는 ISO 시각; 모든 서버 이벤트에 존재하지는 않음 |
| published_at | 외부 발행 시점용 필드; 현재 export 명령은 이 값을 변경하지 않음 |

owner는 SketchEvent의 직접 필드가 아니라 Project를 통해 연결한다. 내보내기는 `schema_version=1`, `source=roompick`, visitor_id 등을 추가한 NDJSON 응답을 만든다. 서비스 표시명을 바꿨다고 이 내부 source·Raw schema·쿠키 이름까지 변경하지 않았다.

## 3. 발생 주체별 행동 이벤트

### 브라우저의 일반 행동 endpoint

일반 행동은 `/api/projects/<project_id>/events/`로 전송한다. 화면에서 실행한 ID 있는 버튼은 `button.clicked`가 함께 생길 수 있다.

| 묶음 | 현재 주요 event_type | 주요 payload·해석 |
| --- | --- | --- |
| Home 시작 | button.clicked | button=start-sketch, page=home |
| 사진 선택·드롭·자르기 선택 | photo.selected, photo.dropped, crop.selected | 바이트·MIME·자르기 영역; 실제 업로드 성공과 별도 |
| 도구·설명·스타일 | tool.changed, requirements.changed, style.changed | 선택값·설명 전문·스타일; 글자 한 개마다의 타이핑 원본은 아님 |
| 획 | stroke.completed, stroke.cancelled | 표시용 stroke 또는 취소 메타데이터; 별도 Raw가 경로·시간을 보충 |
| 삽입·편집 | annotation.added/edited/moved/resized/removed | item 또는 stroke_index·변경 크기 등; 동작에 따라 payload가 다름 |
| 채우기 | fill.applied | 채우기 item·마스크 |
| 선택·그룹·복사 | selection.boxed/grouped/ungrouped/copied/pasted | 요소/획 개수 등; Raw patch로 상세 변화 확인 |
| 편집 기록 | history.undo, history.redo, sketch.cleared | 편집기 작업 이력; 결과 배치 이력과 같은 의미로 쓰지 않음 |
| 생성 클릭 | search.clicked | 현재 내부 event 이름이며 버튼 표시명은 공간 만들기 |
| 결과 배치 | result.moved, result.resized, result.cancelled | 결과·배치 ID, 입력 방식, 관측 가능한 최종 좌표 |
| 비교·재시작·다운로드 | view.changed, redraw.clicked, export.downloaded | 비교 화면·restart mode·PNG 형식·결과 버전 |

현재 결과 가로/세로 입력도 result.resized를 기록한다. 키보드 이동 등 일부 경로에는 x/y/width/height가 생략되므로 최종 배치는 Composition으로 확인한다. 별도 선택 도구 버튼, 사전 가구 품목 선택, 결과 JSON 버튼은 제거됐으므로 과거의 `category.selected`, `item.*`, JSON 다운로드 기록이 있어도 현재 UI에 해당 버튼이 있다는 뜻은 아니다. 서버 validation의 허용 목록과 현재 UI의 실제 호출 목록은 다를 수 있다.

### 서버에서 생성하는 완료·방문 사건

| event_type | 시점 | 성공 판단에 사용할 때 |
| --- | --- | --- |
| home.viewed | Home GET | Project가 방문 용도로도 생기므로 업로드 수와 구분 |
| page.viewed | editor GET | 페이지 조회 기록 |
| project.created | 프로젝트 API 생성 | 사진 없는 작업도 가능 |
| photo.uploaded | 사진 업로드 작업 성공 | 선택/드롭 이벤트보다 서버 성공에 가까움 |
| sketch.saved | 명시적 문서 저장 API 성공 | revision·획/요소 개수 확인 |
| photo.cropped | 자른 사진 작업 성공 | previous_project_id·crop 영역 |
| search.completed | 모의 합성 결과 저장 성공 | result_id·placement_count·mode |
| result.viewed | 결과 페이지 GET | 결과 조회이며 다운로드 완료 아님 |
| result.adjusted | 배치·PNG 저장 성공 | result_id·새 version |
| sketch.restarted | 재시작 작업 생성 | 이전 결과·새 Project·mode 연결 |

모든 API 성공을 대응하는 SketchEvent 이름으로 남기는 것은 아니다. Raw 저장은 samples 응답·JSON 파일, 추천 성공은 RecommendationRun, 검색 품목 수정은 SceneObjectRevision으로 확인한다. 실제 코드에 없는 `raw.saved`, `recommendation.completed`, `category.changed`가 자동으로 저장된다고 가정하지 않는다.

### 상품 반응 전용 endpoint

| event_type | 전송·저장 조건 | 주의 |
| --- | --- | --- |
| PRODUCT_IMPRESSION | 카드 화면 진입 또는 서버의 누락 노출 보충 | item 기반 결정적 ID로 중복 방지; 전부 실제 관측 노출이라고 단정하지 않음 |
| PRODUCT_SELECTED | 마음에 들어요 선택 | recommendation_run_id·item_id·impression_id·mode 연결 |
| PRODUCT_REJECTED | 다른 취향이에요 선택 | 이미 같은 선택 상태인 버튼의 반복 클릭은 새 반응으로 처리하지 않음 |
| COMPARISON_LINK_CLICKED | live 제공자·허용 링크 검증을 통과한 경우에만 | 현재 mock 모드에서는 판매 링크가 비활성이므로 일반 이용에서 발생하지 않음 |

상품 이벤트는 일반 events endpoint 대신 `/api/recommendation-items/<item_id>/events/`를 쓴다. 실제 방문 성공·구매를 수집하는 이벤트는 없다. 노출/반응의 product_id가 null인 모의 샘플을 실제 상품 ID와 섞지 않는다.

## 4. 전송 대기와 거절 기록

| 경로 | 보관 방식 | 재전송·삭제 기준 |
| --- | --- | --- |
| 일반 행동 | localStorage `roompick.events.<visitor>.pending.<event_id>` | 약 1.5초, 성공 확인 뒤 삭제; 영구 입력 오류는 .rejected로 분리 |
| 상품 반응 | localStorage `roompick.product-events.<visitor>.pending.<event_id>` | 약 2초·온라인 복구 시 재전송; 별도 rejected |
| Raw | IndexedDB roompick-sketch-v1의 drafts/outbox/failed | 초안 약 1초 보관, outbox 약 5초 전송; sample_id 성공 확인 후 삭제 |
| 편집·배치 이력 | sessionStorage | 탭 기준 복구; 사용자 계정 이력 DB가 아님 |

종료 시 sendBeacon 호출이 성공했다고 서버 저장이 확인된 것은 아니다. 대기 데이터를 즉시 지우지 않고 중복 허용 ID로 재시도한다. 브라우저 저장소 차단·부족 시 메모리 대체 또는 수집 안내가 나오며 강제 종료 뒤 완전한 전달을 보장하지 않는다.

## 5. HTTP 상태를 해석하는 방법

| 요청·응답 | 확인할 내용 |
| --- | --- |
| events 200 | 서버가 해당 행동 묶음을 받아 저장/중복 확인 |
| samples 201 / 200 | 새 Raw 저장 / 같은 Raw 내용 재전송 성공 |
| scene-generations 또는 search 201 | 새 모의 생성 결과 저장 |
| placements 200 | 현재 조건에 맞는 배치 저장 성공 |
| recommendations 201/200/202 | 새 추천 반영 / 재사용 / 아직 실행 상태; 응답 DTO.status도 함께 확인 |
| revisions 201/200 | 새 검색 조건 수정 / 같은 요청 재사용 |
| 400 / 415 / 422 | 입력·형식·정합성 검증 거부; endpoint별 응답 본문 확인 |
| 403 / 404 | CSRF 또는 소유권·대상·파일 존재 문제 등; 상태만으로 단일 원인을 확정하지 않음 |
| 409 | 작업·배치 버전, 같은 ID 다른 내용, 변경된 물체 등 충돌 |
| 413 | 요청·원본 크기 제한 |
| 502 / 503 | 추천 응답 검증·제공자 연결·Raw 파일 저장 등 서버 처리 실패 |

200만 세어 작업 성공률을 계산하지 않는다. 202는 완료가 아니고, 409는 중복 덮어쓰기를 방어한 정상 거절일 수 있다. 요청 URL에 scene-generations 대신 search가 남아 있어도 호환 경로일 수 있다.

## 6. 서버 로그 파일과 오류 메시지

Django LOGGING에 별도 고정 FileHandler를 설정한 구조는 아니다. 터미널 실행이면 요청·오류가 터미널에 출력되고, 프로세스 stdout/stderr를 리다이렉션해서 실행한 경우 파일에 남는다. 현재 이동 폴더에 `data/runtime/server.stdout.log`, `server.stderr.log`가 존재하지만 이동 전 로그가 포함될 수 있으므로 파일 존재만으로 새 경로의 서버가 실행 중이라고 판단하지 않는다.

| 코드의 메시지 | 발생 지점 | 확인할 것 |
| --- | --- | --- |
| 스케치 원본 저장 실패 | views.collect_sample | 디스크·경로·권한·파일 저장 예외; 클라이언트에는 503 |
| Old composition image cleanup deferred; current result is saved. | views.update_placements | 현재 결과는 저장됐지만 이전 PNG 정리 지연 |
| Recommendation provider failed for run ... | platform_views.recommend | 제공자 예외, 해당 run 상태·metadata |
| Product link provider failed | platform_views.link | live 링크 제공자 오류; 현재 모의 링크와 구분 |

회전·보관·중앙 로그 수집·로그인 사용자 추적 시스템은 구현하지 않았다. 방화벽 로그는 웹 요청 로그와 별개다. DevTools Console과 화면 수집 상태도 확인하되 브라우저 오류가 자동으로 서버에 모두 적재되는 것은 아니다.
