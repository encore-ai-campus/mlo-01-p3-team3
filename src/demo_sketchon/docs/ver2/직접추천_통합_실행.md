## 데이터와 환경 변수

기본 상품은 `src/interior_recommender/sample/crawl_test/full/catalog-with-links/products.json`이다. 사용자가 재사용을 승인한 상품 295개와 기존 벡터를 읽는다. 고유 이미지 290개의 임베딩 모두 SUCCEEDED, 준비 manifest·임베딩 index·이미지·벡터 checksum과 현재 모델/768차원/전처리 호환을 확인했다. 상품 이미지 임베딩 290건을 다시 호출하지 않는다. 95개 상품은 품목 정보 결측으로 기존 정책대로 미확인 후보에 분리된다.

추천 상품 DB·MySQL·Kafka·Delta/Bronze·광고 서버 HTTP·FAISS는 연결하지 않는다. 로그인·세션·기존 Canvas 프로젝트와 신규 추천 작업 원장은 로컬 SQLite를 사용한다. `recommendations/0001_initial` migration을 적용한다. 외부 서비스 DB 스키마 전환은 별도다. 시험 카탈로그의 `test_only=true`와 로컬 실행의 `bronze_verified=false`를 유지한다. 응답에 포함된 상품 이미지만 실행에 복사하며 전체 카탈로그를 매 요청 복제하지 않는다.

## API·입력·권한

아래 경로는 모두 `/interior-recommand/` 기준이다. API 끝에 `/`를 붙이지 않는다.

| 요청 | 동작 |
|---|---|
| `GET api/csrf` | 현재 세션의 CSRF 토큰 |
| `POST api/runs` | 헤더 검사·원본 보존·SQLite QUEUED 접수, 202와 run ID·화면 URL. 변환/추천은 별도 워커 |
| `GET api/runs/{id}` | 상태·해석·추천·작업 조회 |
| `POST api/runs/{id}/actions/prepare` | JSON `{"retry":true}`로 같은 입력·정책 재시도 |
| `GET assets/{id}/{path}` | 소유권 확인 후 manifest 등록 이미지 반환 |
| `GET api/runs/{id}/product-link?image_id=...` | 저장 추천 상품의 허용된 다나와 URL로 302 |

입력은 `photo`(필수, 15MiB 이하), 선택 `sketch`(15MiB 이하, 사진과 같은 크기), `text`, `document`(`strokes/items`, UTF-8 2MiB 이하), UUID `request_id`, 선택 `project`·`requested_region`이다. 사진과 텍스트 또는 스케치가 필요하다. 요청 본문 제한은 35MiB이며 Django 파일 업로드 핸들러를 유지한다. 같은 ID·같은 입력은 기존 run, 다른 입력은 거절한다. 성공한 해석·임베딩·추천은 checksum/receipt 계약에 따라 재사용한다.

회원·비회원 모두 이용한다. 기본 사용자 흐름은 기존 Canvas의 프로젝트에 연결한다. 서버가 프로젝트 권한·revision·편집 사진 바이트를 검사하고, 상태·재시도·이미지·링크 조회도 현재 프로젝트 권한을 재검사하므로 로그인 귀속과 같은 계정의 다른 기기 접근을 따른다. 호환 API로 프로젝트 없이 직접 접수한 실행은 비회원의 브라우저 방문 ID 또는 회원 계정에 귀속하며 비회원 실행의 자동 회원 편입은 지원하지 않는다. 해당 API를 위한 별도 사용자 입력 화면은 제공하지 않는다. 브라우저의 owner·계정·브리지 헤더는 신뢰하지 않는다.

기존 세션·`roompick_csrftoken`과 CSRF 보호를 유지한다. 계정 변경 시 이전 결과/이미지와 늦은 응답을 제거한다. 직접 추천은 공간 생성 하루 3회 제한을 차감하지 않는다. 추천 UUID를 `Composition` 결과 ID로 사용하지 않고 Raw 제출은 `result_id=null`로 둔다. 기존 저장·찜·이미지 비교는 기존 모의 결과 기능으로 유지하며 직접 추천에 자동 확장하지 않는다.

화면은 공통 Sketch · On 로고·계정 헤더·흰 배경·녹색 포인트를 사용한다. 템플릿/정적 파일은 `recommendations/`로 분리한다. 조건 불일치 제외·필수 정보 UNKNOWN 분리·가격/규격 결측 안내를 유지한다. 상품 링크는 저장 상품 대응·HTTPS·호스트·상품번호 검증이며 실시간 판매 유효성이나 판매처 직접 구매 검증을 뜻하지 않는다.

## 검증

프로젝트 폴더에서 `python manage.py check`, `python manage.py test`, `node --test tests/*.test.mjs`를 실행한다. `recommendations/tests.py`는 승인된 카탈로그와 대체 AI로 통합 경로·소유권·계정 전환·CSRF·asset·링크·재전송·성공 단계 재사용을 확인하며 과금 호출을 하지 않는다.

엔진 회귀는 `develop/`에서 `python -m pytest -q -p no:cacheprovider -c src/interior_recommender/pyproject.toml src/interior_recommender/tests`로 실행한다. 브라우저 검증은 Playwright·Edge와 별도 임시 DB/미디어/Raw/출력을 사용하는 DEMO=1 서버에서 `ROOMPICK_TEST_URL`을 맞추고 `node tests/recommendations-browser.cjs`를 실행한다. 320~1440px 화면·브랜드·기존 Canvas 입력→본문/상단/모바일 추천 버튼→읽기 전용 입력 미리보기·상태/결과/이미지·상품 링크·입력 수정 복원을 검사한다. 임시 데이터는 검사 후 정리한다. 실제 API·추천 품질·운영 부하 검증 여부는 별도로 기록한다.

2026-10-16 검증: Django 96개(추천 통합 9개 포함), 추천 엔진 pytest 185개, Node 26개 통과. 실제 Edge에서 위 반응형/Canvas 경로를 확인했다. 예시 방 사진과 ‘창가에 놓을 원목 의자’ 요청으로 기존 Gemini 해석·질의 임베딩도 호출했으며 context/query/ranking 모두 성공했다. 결과는 조건 확인 상품 0개·필수 정보 미확인 후보 6개(UNVERIFIED_ONLY)였고 이미지 200·상품 링크 302를 확인했다. 이를 필수 조건 충족이나 추천 품질 보증으로 기록하지 않는다. 상품 벡터 재생성·이미지 생성·운영 부하 검사는 수행하지 않았다.

입력 흐름 수정: 추천 페이지의 별도 입력 폼을 제거하고 기존 편집기의 주 실행 버튼을 직접 추천으로 연결했다. 재전송 시 입력 저장/revision 갱신을 반복하지 않고 같은 요청 ID를 유지한다.

선호 입력 수정: 선택적 ‘오크 우드’ 등을 사용자 요구 원문에 합쳐 필수 재질로 해석하던 통합 오류를 수정했다. 서버에 저장된 선호는 `external_project.style_preferences`와 `style_policy=search-only-v1`로 고정하고 질의 검색어에만 사용한다. 명시적인 원문 필수 조건과 기존 필터·가중치는 유지한다. 조건 확인 상품이 없고 미확인 후보가 있으면 빈 확인 상품 영역을 숨기고 후보 수와 추가 확인 항목을 표시한다. 과거 run의 원문·해석·벡터·결과는 덮어쓰지 않으며 새 입력 정책은 새 요청에만 적용한다.

추가 검증: Django 97개(추천 통합 10개 포함)·추천 엔진 185개 통과. 선호가 해석용 사용자 원문에 들어가지 않고 검색 질의에만 들어가는지 확인했다. 기존 사용자 요청의 context/query/ranking checksum과 고정 인덱스를 대조해 읽기 전용으로 원인을 검산했고, 잘못 전달된 선호 재질 조건만 분리하면 품목 확인 의자 6개가 반환됨을 확인했다. 과거 실행을 수정하거나 Gemini를 재호출하지 않았다. 샘플 의자 51개 모두 상품 전체 material은 NULL이며 프레임·좌판 원문을 전체 상품 재질로 임의 승격하지 않는다.

## 통합 변경 파일

색상 중심 스타일 수정: 새 요청은 `style_policy=color-first-v2`로 크림 패브릭→아이보리, 오크 우드→밝은 갈색·베이지 톤, 세이지 그린→차분한 초록을 검색 질의에 반영한다. 재질 명칭을 선택 스타일 검색어로 넣지 않고, 확인된 전체 상품 색상이 선호 색상과 맞으면 기존 색상 가중치 0.15를 적용한다. 색상 결측·불일치는 제외하지 않으며 임베딩 색상·톤 유사도도 함께 사용한다. 원문의 명시 색상 EQ 조건/색상 선호가 선택 스타일보다 우선한다. 원본 AI 해석은 보존하고 순위용 색상과 출처는 결과의 `color_preference`로 표시한다. 기존 `search-only-v1` 실행은 변경하지 않는다.

색상 정책 검증: Django 98개·엔진 전체 194개 통과 후 명시 색상 EQ 우선순위 검사를 추가해 스타일 관련 10개를 다시 통과했다. 세 선택지의 색상 질의·색상 가중치·원본 해석 보존·원문 색상 우선·과거 스타일 정책 호환을 검사했다. 프런트 모듈 문법과 실제 편집기의 색상·톤 안내를 확인했으며 Gemini 호출·상품 벡터 재생성은 하지 않았다.

재질 정책 수정: 기본 `weighted-content-v2`에서 재질은 필수 제외/UNKNOWN 분리 조건이 아닌 질의 임베딩 참고다. 명시 재질의 원문 인용을 검색어에 넣고, 재질 대조는 별도 `preference_checks`로 제공한다. 재질 정보가 없거나 달라도 추천에 포함하며 화면에 이 기준을 안내한다. 기존 색상 가중치·품목·가격·치수 등 나머지 조건은 유지한다. 새 요청부터 적용하며 저장된 v1 run의 정책·결과는 유지한다. 새 결과를 보려면 ‘입력 수정하기’에서 ‘상품 추천받기’로 새 요청을 보낸다.

재질 정책 검증: Django 98개(추천 통합 11개), 추천 엔진 187개, Node 26개 통과. 승인된 295개 상품과 대체 AI로 명시 ‘원목’ 조건의 질의 포함 및 material=NULL인 의자 6개 정상 추천을 확인했다. 재질 EQ/NE의 결측·불일치 비제외와 가격·품목의 기존 제외/UNKNOWN 처리, v1 정책 호환도 검사했다. 상품 벡터 재생성·과거 run 수정·추가 Gemini 호출은 하지 않았다.
