## 1. 기존 기준과 확장 반영 방향

기존 데모는 사용자가 플랫폼에서 어떤 기능을 사용하고 어떤 편집을 완료했는지를 `SketchEvent`에 기록했다. 완료된 획의 좌표도 기록하지만, 각 점의 시간이나 포인터 상태까지 보존하는 학습용 원본 계약은 없었다.

3차에서는 기존 행동 이벤트를 유지하면서 별도 수집기를 연결했다. 펜·지우개의 원본 좌표와 시간, 취소 경로, 편집 대상, 시작 문서와 최종 상태를 하나의 원본 샘플에 보관한다. 수집·전송 실패가 기존 편집·검색을 실패시키지 않도록 기존 문서와 수집 API를 분리했다.

초기 화면에는 방문 기록이 있었지만 ‘내 공간 꾸미기’ 클릭 기록은 없었으므로 추가했다. 결과 화면의 버튼 클릭·가구 이동·크기 조절·다운로드·재시작 기록은 이미 있었으며 그대로 유지한다.

| 항목 | 기존 데모 기준 | 3차 확장 반영 |
|---|---|---|
| 수집 목적 | 기능 사용과 편집 완료 기록 | 기존 행동 분석 + 스케치 생성 과정의 원본 보존 |
| 기록 단위 | 개별 행동 이벤트, 현재 작업 문서, 검색 입력 스냅샷 | 기존 기록에 편집 구간별 원본 샘플을 추가 |
| 좌표 | 0~1 범위로 제한, 소수점 6자리 반올림, 가까운 점 생략 | 별도 원본에서는 화면 밖 좌표와 정밀도를 보존. `in_bounds`로 구분 |
| 시간 | 클라이언트 행동 시각과 서버 수신 시각 | 각 원본 점의 상대 시간 `t` 추가 |
| 포인터 상태 | 획 완료·취소 이벤트 | 점마다 down/move/up/cancel, native/coalesced/synthetic 기록 |
| 입력 메타데이터 | 입력 장치, 필압, 선택 색상·두께 | CSS 캔버스 크기, DPR, 원본 필압, 펜 기울기 추가 |
| 취소된 획 | 취소 이벤트에 입력 장치 등 일부 정보 | 취소 전 좌표와 종료 이유 보존 |
| Undo/Redo/Clear | 실행 이벤트와 일부 작업 정보 | 변경 대상 ID, 변경분, 재생 가능한 문서 상태 보존 |
| 부분 지우기 | 편집 문서의 지우기 마스크와 완료 이벤트 | 원본 지우개 경로 ID와 영향을 받은 요소 ID를 연결 |
| 브라우저 보관 | 미전송 이벤트는 localStorage, 편집 이력은 sessionStorage | 원본 초안·전송 대기·검토 필요 정보는 IndexedDB에 별도 보관 |
| 서버 보관 | SQLite의 Project·SketchEvent·Composition 및 추천·검색 수정 기록 | 불변 원본 JSON 파일 추가 |
| 초기 화면 시작 클릭 | 미수집 | 기존 이벤트 API로 추가 수집 |
| 결과 화면 조작 | 기존에 수집 | 유지. 스케치 원본 좌표 수집과 구분 |

## 2. 화면별 행동 이벤트 기준

### 2.1 초기 화면

| 기능 연결 | 행동 | 이벤트 | 기준 및 변경 사항 |
|---|---|---|---|
| HOME-01~04 | 초기 화면 접속 | `home.viewed` | 기존 서버 기록 유지 |
| HOME-02 | 내 공간 꾸미기 클릭 | `button.clicked` | 추가. `button=start-sketch`, `page=home` 기록. 기존 링크 이동을 유지 |

초기 화면 접속 시 생성된 작업에 클릭 이벤트를 연결한다. 클릭 후 스케치 화면의 작업 ID가 달라져도 같은 방문 ID로 연결할 수 있다. 클릭 전송은 화면 이동을 기다리게 하지 않으며, 미전송 기록은 기존 큐에서 재전송한다.

## 3. 스케치 원본 수집 계약

### 3.1 원본 샘플 단위

원본 샘플은 한 브라우저 탭에서 같은 프로젝트를 편집한 구간이다. 다음 시점에 구간을 종료하고 자동 제출한다.

| 종료 시점 | `submission_reason` | 처리 |
|---|---|---|
| 모의 검색 성공 | `search` | 결과 ID 연결 후 제출. 별도 Submit 버튼은 추가하지 않음 |
| 사진 교체·자르기·이전 사진 복원 등 작업 ID 변경 | `project_changed` | 이전 프로젝트 구간 제출, 새 프로젝트에서 수집 시작 |
| 페이지 종료·이동·새로고침 | `page_exit` | 보관·전송 시도. 종료 시 완전한 전달을 보장하지 않음 |
| 이전 탭의 미제출 초안 복구 | `recovered` | 작성자가 종료됐음을 잠금으로 확인한 뒤 이전 초안을 별도 제출 |
| 원본 수집 한도 도달 | `capture_limit` | 한도까지의 원본과 마지막 기록 상태 보관. 이후 원본 수집 중단을 표시 |

빈 최종 문서나 취소 이력이 있는 구간도 원본으로 보관할 수 있으며 품질 검토 대상으로 표시한다. 단일 객체의 정답 라벨을 제시하고 제출받는 첨부 예제와 달리, 현재 데모는 사진 위의 자유 스케치를 수집한다.

### 3.2 Sample 필드

| 필드 | 기준 |
|---|---|
| `schema_version` | `roompick-sketch-1.0.0`. 첨부 예제의 스키마와 그대로 호환된다고 가정하지 않음 |
| `sample_id` | 수집 구간의 UUID. 재전송에도 같은 ID·내용 유지 |
| `project_id` | 해당 원본의 작업 ID |
| `writer_id` | 기존 익명 방문 ID. 서버는 현재 세션의 작업 소유자와 일치하는지 검증 |
| `created_at` | 샘플 생성 UTC 시각 |
| `label_id`, `label_status` | `null`, `unverified`. 자유 그림이나 모의 추천 결과를 정답으로 확정하지 않음 |
| `quality_status` | 원본은 `pending`. 서버 판정으로 원본 파일을 덮어쓰지 않음 |
| `coordinate_system` | `normalized_xy_top_left_down` |
| `time_origin` | `first_pointerdown_ms`. 해당 구간에서 처음 기록한 펜·지우개 down 기준 |
| `canvas_width`, `canvas_height` | 원본 수집 기준 캔버스 CSS 크기 |
| `device_pixel_ratio` | 화면 DPR. 물리적 펜 이동 거리 단위가 아님 |
| `project_width`, `project_height` | 편집용 사진·작업 크기. CSS 캔버스 크기 및 업로드 바이트 원본의 화소 크기와 구분 |
| `strokes` | 펜·지우개 원본 경로. 취소·삭제된 경로도 보존 |
| `operations` | 편집 및 기능 사용 이력, 변경 대상과 변경분 |
| `initial_document`, `final_document` | 구간 시작 문서와 마지막 기록 상태. 기존 편집 문서 형식을 유지 |
| `final_active_stroke_ids` | 최종 문서에 남은 펜 획 ID. 실제 보이는 영역은 부분 지우기 마스크도 함께 해석해야 함 |
| `duration_ms` | 마지막 기록까지의 상대 시간. 펜을 움직인 시간만의 합은 아님 |
| `undo_count` | 원본 작업 이력에서 `history.undo`의 개수 |
| `submission_reason`, `result_id` | 구간 종료 사유와 해당하는 경우 검색 결과 ID |
| `capture_status` | `complete` 또는 `limited`. 한도 종료 샘플은 최종 검색 결과 전체를 대표하지 않음 |

펜·지우개를 처음 사용하기 전의 원본 작업 이력은 상대 시간 `t=0`으로 기록된다. 그 이전 행동의 절대 발생 시각과 상세 payload는 기존 행동 이벤트에서 확인한다.

### 3.3 Stroke·Point 필드

| 구분 | 필드 | 기준 |
|---|---|---|
| 획 | `stroke_id`, `stroke_order` | 원본 경로의 UUID와 수집 순서. 삭제해도 원본 번호를 다시 매기지 않음 |
| 획 | `tool`, `ink_hex`, `stroke_width_css_px` | 펜/지우개, 선택 색상, 수집 당시 CSS 두께 |
| 획 | `pointer_type` | mouse/touch/pen/unknown |
| 획 | `canvas_width`, `canvas_height`, `device_pixel_ratio` | 해당 경로 수집 당시의 크기와 DPR |
| 획 | `end_reason` | up/cancel/lost_capture/interrupted/limited |
| 점 | `x`, `y` | `(client 좌표 - 캔버스 위치) / CSS 크기`. 원본에서는 범위 제한·반올림하지 않음 |
| 점 | `t` | 해당 구간의 시간 원점 기준 밀리초 |
| 점 | `event_type` | down/move/up/cancel |
| 점 | `source` | native/coalesced/synthetic |
| 점 | `in_bounds` | x·y가 모두 0~1 안인지 표시 |
| 점 | `pressure` | 브라우저가 제공한 유한값. 원본에서는 0도 0으로 보존 |
| 점 | `tilt_x`, `tilt_y` | 펜이 제공한 기울기. 사용 가능한 경우만 보관 |
| 점 | `canvas_width`, `canvas_height` | 획 중 CSS 크기가 달라진 경우 해당 점에 추가 기록 |

원본 수집은 가까운 점을 기존 그림판 기준으로 생략하지 않는다. 동일 좌표·시각의 중복 전달과 이미 기록한 시각보다 오래된 전달은 중복·순서 관리를 위해 생략한다. 기존 그림판의 좌표 제한, 반올림, 표시용 점 간격 처리와 필압 처리 방식은 변경하지 않았다.

### 3.4 편집 작업과 부분 지우기

각 Operation에는 `op_id`, 행동 종류 `type`, 상대 시간 `t`, 클라이언트 시각, 영향을 받은 획·요소 ID를 보관한다. 기존 행동 이벤트와 연결 가능한 작업에는 `event_id`를 추가한다. 펜·지우개 완료·취소 작업에는 해당 원본의 `source_stroke_id`를 연결한다.

상태가 바뀌면 `document_patch`에 strokes/items별 추가·변경 요소, 삭제 ID, 최종 순서를 기록한다. 서버는 시작 문서에 변경분을 순서대로 적용하고 최종 문서와 일치하는지 검증한다.

- Undo/Redo/Clear로 없어지거나 돌아오는 요소를 변경분으로 표현한다.
- 지우개는 현재의 픽셀 범위 부분 지우기를 유지한다. 첨부 collector의 획 전체 삭제 방식으로 교체하지 않았다.
- 부분 지우기 변경분에는 기존 요소의 `cuts`가 포함된다. 원본 경로와 영향을 받은 요소를 연결하고, 최종 상태 재생에는 이 마스크를 적용한다.
- 이동·크기 조절·그룹·복사·붙여넣기·텍스트·도형·채우기도 현재 문서 상태의 변경분으로 표현한다.
- 이전 작업에서 복원한 획은 시작 문서의 기존 좌표로 보존한다. 과거에 수집하지 않은 점별 시간을 만들어 넣지 않는다.

## 4. 저장·전송 흐름

### 4.1 기존 행동 이벤트

브라우저 기능 실행 → 기존 전송 큐 → `/api/projects/<project_id>/events/` → SQLite의 `SketchEvent`.

약 1.5초 주기의 전송과 일부 동작 완료 직후 전송, 온라인 복귀 시 재전송, 페이지 종료 시 sendBeacon 시도를 유지한다. 이벤트 UUID로 중복을 검사한다. 미전송 기록은 localStorage의 `roompick.events.<visitor_id>.pending.<event_id>`에 이벤트별로 보관한다. 영구 거절은 같은 namespace의 `.rejected.<event_id>`로 분리한다.

### 4.2 새 스케치 원본

별도 수집기 → IndexedDB 초안 → 구간 종료 후 outbox → `/api/projects/<project_id>/samples/` → 불변 JSON.

| 위치 | 내용 |
|---|---|
| IndexedDB `roompick-sketch-v1`, 버전 2, `drafts` | 작성 중인 원본 초안, 탭 식별 정보 |
| 같은 DB의 `outbox` | 서버 성공 응답을 아직 확인하지 못한 샘플 |
| 같은 DB의 `failed` | 자동 재시도에서 분리한 검토 필요 샘플의 HTTP 상태·오류. 원본은 outbox에 유지 |
| `C:\mlo-01-p3-team3\src\demo_sketchon\data\sketch_raw\<sample_id>.json` | 정상 검증을 통과해 저장한 서버 원본 |
| `demo_sketchon/db.sqlite3` | 기존 작업·행동 이벤트·검색 결과 메타데이터 |
| `demo_sketchon/media/` | 기존 공간 사진과 모의 합성 결과 이미지 |

초안은 동작 완료 시점과 작성 중 약 1초 간격으로 보관한다. 구간 종료 시 초안을 outbox로 옮기고, 서버가 해당 샘플 ID의 성공을 확인하면 로컬 전송 대기 기록을 삭제한다. 재전송은 스케치 화면에서 약 5초 간격·온라인 복귀·다음 접속 시 시도한다.

페이지 종료 시에는 이미 로컬에 확정 보관된 작은 outbox 샘플에 한해 sendBeacon을 추가로 시도한다. beacon 호출은 저장 성공 응답이 아니므로 로컬 기록을 삭제하지 않는다.

4xx 입력 오류·샘플 충돌·없는 작업은 검토 필요로 분리하고 다른 샘플의 전송을 계속한다. 네트워크 장애와 서버 저장 장애는 재전송 대상으로 유지한다. 원본 저장 폴더는 첫 정상 제출 시 생성되며 정적 경로로 공개하지 않고 Git 제외 대상에 넣었다.

### 4.3 새로고침·복제 탭 처리

새로고침 이후에는 이전 샘플에 새 포인터 시간 원점을 이어 붙이지 않는다. 작성 탭이 종료된 초안은 기존 시간 기록 그대로 제출하고 새 구간을 시작한다. 중간에 끊긴 원본은 관측한 마지막 위치를 synthetic cancel로 표시한다.

localhost/HTTPS 등 Web Locks를 사용할 수 있는 환경에서는 원본 작성자가 샘플별 잠금을 유지한다. 복구 시 잠금을 획득한 뒤 초안과 outbox를 다시 확인하고, 이미 확정된 샘플이나 다른 탭이 작성 중인 초안은 복구 제출하지 않는다.

LAN의 일반 HTTP처럼 Web Locks를 사용할 수 없는 환경에서는 작성 중 초안을 자동으로 확정하지 않고 IndexedDB에 보관한다. 정상 구간 종료와 이미 outbox에 보관된 샘플의 전송은 계속 지원한다. 이 제약은 원본 자동 복구에 대한 것으로 기존 화면의 편집 복원 기능을 변경하지 않는다.

## 5. 서버 검증과 원본 불변 저장

- 기존 세션 소유권과 Django CSRF 검증을 적용한다.
- UTF-8 JSON, NaN·Infinity 금지, 최대 요청 크기를 검사한다.
- 계약 버전·필드, UUID, 시각, 유한한 좌표·시간·메타데이터를 검사한다.
- 획 순서·점 시간·시작/종료 이벤트·in_bounds·원본 ID 중복을 검사한다.
- 편집 변경분을 재생하고 최종 문서·최종 획 ID·Undo 횟수와 일치하는지 검사한다.
- 라벨은 `null/unverified`, 클라이언트 품질 상태는 `pending`만 허용한다.
- 임시 파일에 기록하고 flush/fsync 후 같은 파일 시스템의 hard link로 확정해 기존 원본을 덮어쓰지 않는다.
- 동일 ID·동일 정규화 JSON은 HTTP 200 중복 성공, 동일 ID·다른 내용은 HTTP 409로 거부한다.

입력 계약은 `raw_samples.py`의 명시적 검증 코드로 적용했다. 첨부 패키지의 JSON Schema 파일이나 FastAPI 서버를 별도 서비스로 추가하지 않았다.

| 판정 | 의미 |
|---|---|
| `pass` | 구조·이력 검증 통과, 현재 검사에서 품질 경고 없음 |
| `review` | 화면 밖 좌표, 크기 변화, 취소/합성 점, 빈 최종 문서, 복원된 기존 좌표, 수집 한도 등의 검토 사항 있음 |
| `quarantine` | 구조·시간·ID·재생 정합성이 잘못되어 API에서 거부. 서버 Raw에 저장하지 않고 로컬 검토 대상으로 보관 |

서버 판정과 warnings는 응답으로 반환한다. Raw의 `quality_status=pending`을 판정값으로 바꾸지 않는다. 별도 Curated 인덱스와 검수·학습 데이터셋 파이프라인은 아직 구현하지 않았다. `pass`도 객체 라벨의 정답이나 학습 사용 승인을 뜻하지 않는다.

## 6. 크기 한도와 수집 실패 처리

서버는 샘플당 4MiB, 1,000개 원본 획, 100,000개 원본 점, 1,000개 작업 이력을 허용한다. 브라우저는 제출 한도를 넘기기 전에 약 3MiB, 900획, 90,000점, 950개 작업 기준으로 해당 구간의 원본 수집을 종료한다.

한도 샘플은 `capture_status=limited`, `submission_reason=capture_limit`로 보관하고 품질 검토 대상으로 반환한다. 마지막으로 기록한 편집 상태를 보관하므로 이후 사용자가 계속 편집한 최종 검색 문서와 같다고 가정하면 안 된다. 스케치 화면 하단에 한도 이후 원본이 수집되지 않는다고 표시한다. 새 프로젝트나 새로고침에서는 새 구간을 시작할 수 있다.

기존 문서 자체가 원본 요청에 담기 어려울 정도로 큰 경우에도 원본 수집의 제약을 안내한다. 기존 편집 기능과 행동 이벤트는 계속 동작한다. 장시간 편집을 원본 손실 없이 연속 수집하려면 추후 구간 연결·청크 전송 설계가 필요하다.

수집 상태는 별도 하단 표시를 사용해 기존 편집 안내를 덮어쓰지 않는다. 저장 공간 차단·용량 부족·쿠키 변경·프로세스 강제 종료 등에서는 원본과 기존 이벤트의 완전한 전달을 보장하지 않는다.

## 9. 검증 범위와 코드 근거

검증에는 기존 실제 DB·사진 대신 별도 임시 DB·미디어·원본 저장소를 사용한다.

원본 수집 최초 확장 당시 Django 테스트 37개, JavaScript 테스트 17개, 기존 Edge 화면 회귀 테스트와 추가 원본 수집 브라우저 테스트를 통과했다. Django 시스템 검사에서도 문제가 없었다. 추가 브라우저 테스트는 실제로 저장된 원본 JSON과 전송 샘플 내용이 같은지 확인한다.
