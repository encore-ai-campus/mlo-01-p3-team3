# RoomPick — 3차 행동데이터 및 로그 확인 명령어

- 작성일: 2026년 10월 14일
- 실행 환경: VS Code의 PowerShell 터미널
- 실행 위치: 현재 폴더가 `roompick`인 상태
- 서버 실행 터미널은 유지하고, 조회용 터미널을 하나 더 연다.
- DB 조회·이벤트 출력 명령은 데이터를 변경하지 않는다. 마지막 로그 저장용 실행 명령은 로그 파일을 생성한다.

## 1. 행동데이터 누적 건수 확인

```powershell
python manage.py shell --no-imports -c "from sketch.models import Project, SketchEvent, Composition; print('작업:', Project.objects.count()); print('행동 이벤트:', SketchEvent.objects.count()); print('생성 결과:', Composition.objects.count())"
```

브라우저에서 행동한 전후에 실행해 이벤트 건수가 늘어나는지 확인한다. 행동 이벤트 한 건은 스케치 한 개를 뜻하지 않는다.

## 2. 최근 행동과 상세 데이터 확인

```powershell
python manage.py shell --no-imports -c "import json; from sketch.models import SketchEvent; rows=list(SketchEvent.objects.order_by('-event_time').values('event_type','event_time','project_id','payload')[:10]); print(json.dumps(rows, default=str, ensure_ascii=False, indent=2))"
```

| 확인 항목 | 의미 |
|---|---|
| `event_type` | 버튼 클릭·획 완료·결과 이동 등의 행동 종류 |
| `event_time` | 서버에 기록된 시각 |
| `project_id` | 행동이 발생한 작업 ID |
| `payload` | 버튼 ID·좌표·입력 장치 등 상세 정보 |
| `payload.client_time` | 브라우저에서 행동을 기록한 시각 |

`event_time`은 출력에서 UTC인 `+00:00`으로 보일 수 있다. 한국 시각은 9시간을 더하면 된다.

## 3. 행동 종류별 건수 확인

```powershell
python manage.py shell --no-imports -c "from django.db.models import Count; from sketch.models import SketchEvent; rows=SketchEvent.objects.values('event_type').annotate(count=Count('event_id')).order_by('-count'); print(*[str(row) for row in rows], sep='\n')"
```

예를 들어 `button.clicked`, `stroke.completed`, `history.undo`, `result.moved`가 각각 몇 건인지 확인할 수 있다.

## 4. 화면을 조작하면서 자동 갱신으로 확인

아래 명령은 2초마다 전체 건수와 최근 행동 5건을 표시한다. 종료는 `Ctrl+C`다.

```powershell
while ($true) {
    Clear-Host
    python manage.py shell --no-imports -c "from sketch.models import SketchEvent; print('전체 이벤트:', SketchEvent.objects.count()); rows=SketchEvent.objects.order_by('-event_time').values('event_type','event_time','payload')[:5]; print(*[str(row) for row in rows], sep='\n')"
    Start-Sleep -Seconds 2
}
```

이 명령을 켜두고 브라우저에서 다음을 실행한다.

| 화면에서 실행할 행동 | 확인할 이벤트 |
|---|---|
| 초기 화면 시작 버튼 클릭 | `button.clicked`, 버튼 값 `start-sketch` |
| 펜·지우개 선택 | `tool.changed` |
| 선 그리기 완료 | `stroke.completed` |
| 실행 취소·다시 실행 | `history.undo`, `history.redo` |
| 상품 검색 | `search.clicked`, `search.completed` |
| 결과 가구 이미지 이동 | `result.moved`, 저장 성공 시 `result.adjusted` |
| 결과 이미지 다운로드 실행 | `export.downloaded` |

## 5. 전체 행동 이벤트 출력

```powershell
python manage.py export_sketch_events
```

특정 작업만 확인하려면 실제 작업 UUID를 넣는다.

```powershell
python manage.py export_sketch_events --project "실제-작업-UUID"
```

위 DB 조회·출력 명령은 기존 데이터나 `published_at`을 변경하지 않는다. Kafka 전송이나 소비 위치 변경도 하지 않는다.

## 6. 스케치 원본 JSON 생성 확인

펜·지우개로 작업한 뒤 상품 검색을 성공시키면 원본 제출을 확인하기 쉽다. 그리는 중에는 브라우저 초안에만 있을 수 있다.

```powershell
$rawPath = '.\data\sketch_raw'

if (Test-Path -LiteralPath $rawPath) {
    $rawFiles = @(Get-ChildItem -LiteralPath $rawPath -Filter *.json)
    "원본 JSON: $($rawFiles.Count)개"

    $rawFiles |
        Sort-Object LastWriteTime -Descending |
        Select-Object -First 5 Name, Length, LastWriteTime
} else {
    '원본 폴더가 없습니다. 아직 첫 정상 제출이 완료되지 않았습니다.'
}
```

최신 파일의 내용은 다음처럼 확인한다.

```powershell
$latestRaw = Get-ChildItem -LiteralPath .\data\sketch_raw `
    -Filter *.json -ErrorAction SilentlyContinue |
    Sort-Object LastWriteTime -Descending |
    Select-Object -First 1

if ($latestRaw) {
    $sample = Get-Content -LiteralPath $latestRaw.FullName -Raw -Encoding utf8 |
        ConvertFrom-Json

    $sample | Select-Object sample_id, project_id, submission_reason,
        capture_status, duration_ms, undo_count, quality_status

    "원본 획: $(@($sample.strokes).Count)개"
    "편집 이력: $(@($sample.operations).Count)개"

    if (@($sample.strokes).Count -gt 0) {
        $sample.strokes[0].points |
            Select-Object -First 5 x, y, t, event_type, source, in_bounds, pressure
    }

    $sample.operations |
        Select-Object -Last 5 type, t, source_stroke_id,
            target_stroke_ids, target_item_ids
} else {
    '확인할 원본 JSON이 없습니다.'
}
```

확인할 핵심은 다음과 같다.

| 원본 필드 | 확인 내용 |
|---|---|
| `strokes[].points` | 좌표·시간·down/move/up/cancel 기록 |
| `strokes[].tool` | 펜인지 지우개인지 |
| `operations` | Undo/Redo/Clear 등의 편집 이력 |
| `submission_reason` | 검색·작업 변경 등 제출 사유 |
| `capture_status` | `complete` 또는 한도 종료인 `limited` |

원본 파일의 `quality_status`는 `pending`으로 유지하도록 구현했으므로, `pending` 자체가 저장 실패를 뜻하지 않는다.

## 7. 원본이 서버에 없을 때 브라우저 확인

`F12 → Application → IndexedDB → roompick-sketch-v1`을 확인한다.

| 저장소 | 상태 |
|---|---|
| `drafts` | 아직 작성 중이거나 종료되지 않은 초안 |
| `outbox` | 서버 성공 응답을 확인하지 못한 원본 |
| `failed` | 입력 오류·충돌 등으로 검토가 필요한 정보 |

DB 행동 이벤트가 늘어도 원본 제출은 실패할 수 있으므로 DB 이벤트와 원본 파일을 각각 확인한다. 일반 LAN HTTP에서는 작성 중 초안의 자동 복구가 제한되며, 상세 제약은 수집기준 문서를 참고한다.

## 8. Django 서버 로그 확인

현재 서버 요청·오류 로그는 Django 서버를 실행한 터미널에서 확인한다. 별도의 로그 파일 저장 설정은 없다.

| 요청과 응답 | 의미 |
|---|---|
| `POST .../events/` → `200` | 행동 이벤트 저장 성공 |
| `POST .../samples/` → `201` | 새 원본 저장 성공 |
| `POST .../samples/` → `200` | 동일 원본 재전송 성공 |
| `POST .../search/` → `201` | 모의 결과 생성 성공 |
| `POST .../placements/` → `200` | 결과 배치 저장 성공 |
| `403` | CSRF 등의 검증에서 거부 |
| `413` | 크기 한도 초과 |
| `422` | 원본 데이터 검증 실패 |
| `409` | 원본 내용 또는 작업 버전 충돌 |

서버 로그에는 개별 좌표 전체가 출력되지 않는다. 상세 행동은 DB, 상세 원본은 JSON에서 확인한다.

서버 로그를 파일로도 남기려면 기존 서버를 종료하고 아래 방식으로 실행한다. 로컬 확인용이며 `roompick-server.log`를 생성한다.

```powershell
python -u manage.py runserver 127.0.0.1:8003 --noreload 2>&1 |
    Tee-Object -FilePath .\roompick-server.log
```

다른 터미널에서 실시간으로 읽는다.

```powershell
Get-Content -LiteralPath .\roompick-server.log -Tail 30 -Wait
```

종료는 `Ctrl+C`다. `--noreload`에서는 코드 변경 후 서버를 직접 재시작해야 한다. 기존 `lan-firewall.log`는 방화벽 설정 기록이며 Django 로그와는 별개다.

## 확인 시 주의사항

페이지 종료·강제 종료 시에는 원본 전송이 완료되지 않을 수 있으므로 IndexedDB 상태도 함께 확인한다. 이 문서의 파일 조회에서 사용하는 `-ErrorAction SilentlyContinue`는 경로 없음 외의 접근 오류도 숨길 수 있으므로, 원인 진단 시에는 해당 옵션을 빼고 오류를 확인한다.
