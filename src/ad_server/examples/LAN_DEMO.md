# 내부망 광고 운영 시연

`examples/run_lan_demo.py --lan-host <이 PC의 내부망 IPv4>`를 ad_server 가상환경의 Python으로 실행한다. 기본 포트는 8004이며 사용 중이면 기존 서버를 임의로 종료하지 않고 중단한다. 실행 전에 의도한 시연 서버만 종료해야 한다.

- DB: `runtime/lan_demo/ads-demo.sqlite3`. 기존 `runtime/ads.sqlite3`와 MySQL은 사용하지 않는다.
- 계정: demo_operator. 첫 생성 시 임시 비밀번호를 실행 터미널에 한 번 출력한다. 재실행은 기존 비밀번호를 유지하며 `--reset-password`를 명시했을 때만 새로 생성한다. 비밀번호·서비스 키는 파일에 저장하지 않는다. DB에는 Django 비밀번호 해시만 보관한다.
- 모의 정책: `runtime/lan_demo/policy.json`. 기본 예시 정책을 복사한 테스트 전용 값이다.
- 관리자: `/admin/`. 광고주·모의 계약·캠페인·제출 버전 등록·심사·활성화.
- 시연: `/sandbox/`. 새 맥락 선정, 같은 요청 재전송, 배너 클릭, 성과 조회.
- 예제: alpha 700포인트, beta 500포인트의 경쟁 캠페인. 둘 다 활성·승인 상태이면 alpha가 선정된다. alpha의 enabled를 끄면 beta가 선정된다. 가명 방문자별 빈도 제한도 적용된다.
- 계약·소재·기간·위치·승인 조건을 충족해야 한다. 입찰값 변경은 기존 버전 수정 대신 새 Revision 제출→승인→Campaign 활성화 순서다.
- 서버 재실행 시 서명 키가 새로 생성되어 이전 로그인·광고 서명은 유지되지 않는다. 기존 관리자 비밀번호와 시연 DB 데이터는 유지한다.
- `runtime/lan_demo/server.pid`, stdout/stderr 로그로 실행 상태를 확인한다. 실제 결제·CPC 차감은 없다.

HTTP 내부망에서도 모의 화면의 가명 UUID를 생성하도록 Web Crypto 난수 기반 대체 경로를 사용한다. 시연 전용 세션·CSRF 쿠키를 분리했다. 이 단독 실행기는 UI를 시작하지 않는다. 현재 UI에는 별도 광고 중계가 구현되어 있으며, 통합 실행은 두 서버의 공통 토큰 설정이 필요하다.

## 처음부터 새 광고 등록하기

관리자 홈에서 **새 광고 등록 시작**을 누른다. 각 화면 아래의 다음 단계 버튼으로 진행한다. 상태 변경과 심사·집행은 운영자가 명시적으로 선택하며 자동 승인하지 않는다.

| 순서 | 할 일 | 다음 버튼 |
|---|---|---|
| 1. 광고주 | 업체 이름 입력, 상태 ‘사용 중’ 선택 | 저장하고 계약 등록 |
| 2. 계약 | 자동 연결된 광고주·기간 확인, 상태 ‘승인’ 선택 | 저장하고 캠페인 만들기 |
| 3. 캠페인 | 자동 연결된 광고주·계약·이름 확인. 집행은 아직 끔 | 저장하고 광고 버전 작성 |
| 4. 광고 작성 | 배너·제목·포인트·표시 위치·기간·이동 주소 확인 | 제출하고 심사 화면으로 |
| 5. 심사 | 제출 내용을 읽고 두 글자 이상 심사 사유 입력 | 승인하고 집행 설정으로 |
| 6. 집행 | ‘광고 집행 켜기’ 체크 | 집행 설정 저장하고 배너 확인 |
| 7. 출력 확인 | 관심 품목을 지정하지 않은 상태에서 광고 선정 | 광고 선정하기 |

시연 등록에서는 브랜드 배너·일반 후보·900포인트·PC 두 위치·테스트 상세 주소를 보이는 기본값으로 채운다. 제출 전에 수정할 수 있다. 계약과 광고 기간은 현재 시각을 포함해야 한다. 계약 미승인·광고주 사용 중 아님 상태는 다음 단계에서 확인하도록 안내하며 자동으로 변경하지 않는다.

새 광고는 다른 적격 후보와 비교한다. 기존 700/500포인트 예제만 활성이고 나머지 조건을 충족하면 새 900포인트 광고가 선정된다. 관련 후보 우선·빈도 제한·동점 규칙에 따라 결과가 달라질 수 있으며 새 광고를 강제로 노출하지 않는다. 선정 후 배너·선정 이유·입찰 비교·실제 표시/클릭 집계를 확인한다.

승인해도 집행은 꺼진 상태다. 반려되었거나 제출 내용을 바꾸려면 상세 화면의 ‘내용을 수정해 새 버전 작성’을 사용한다. 기존 목록의 승인 작업도 유지한다. 새 직접 심사 경로는 POST·CSRF·심사/캠페인 변경 권한을 요구하고 기존 심사 엔진으로 최신 버전만 처리한다.

이 실행기의 출력 확인은 광고 서버 독립 시연이다. 현재 서비스 편집·추천 결과 UI 연결 구현과 구분한다. DB 필드·API 값·입찰 정책은 유지한다.

## 비딩 화면 읽기

- 시연 조건의 관심 품목·확인 근거·표시 위치를 선택하고 ‘광고 선정하기’를 누른다.
- 이번 광고 선정 결과에서 한글 선정 이유와 후보별 포인트·선정 여부를 확인한다. 관련 광고 우선과 광고주별 대표 선정 규칙은 그대로 적용된다.
- 이번 광고의 반응은 해당 선정의 이미지 표시·가시 노출·유효 클릭을 구분한다. 가시 노출은 활성 화면에서 배너 면적 50% 이상이 연속 1초 보일 때 인정한다.
- 전체 시연 누적 현황은 시연 DB의 모든 운영자 기록이며 현재 브라우저만의 기록이 아니다. 중복·진단 사건은 정상 성과에 가산하지 않는다. 표시가 0회이면 클릭률을 계산하지 않는다.
- 후보 포인트는 선정 당시 기록이다. 비교표의 이름은 현재 등록명을 함께 사용한다. 원문은 접힌 ‘개발용 상세 정보’에서만 확인한다.
- ‘같은 요청 다시 확인’은 기존 선정 결과를 재사용한다. 만료·중지된 결과도 새 광고를 자동 선정하지 않는다.

격리된 테스트 DB에서 88개 테스트를 통과했고 실제 내부망 주소의 Edge에서 PC·모바일 선정·노출·클릭·현황 갱신을 확인했다. 이 단독 시연 절차는 기존 UI DB와 실제 운영 DB를 변경하지 않는다.
