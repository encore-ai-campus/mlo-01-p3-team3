# 이미지 재개 이력 확인 비용 개선

2026-10-27. 실제 수집 폴더는 변경하거나 전체 다운로드를 재시작하지 않았다. 아래는 개선 당시의 검증 기록이다. 현재 다운로드가 사용했던 기존 버전 `67e837d`의 누락된 소스·테스트·설정만 복원한 뒤 개선했으며 기존 수정 파일은 덮어쓰지 않았다.

## 변경 내용

- 기존: URL 처음부터 파일 SHA-256을 반복 확인하고 25개마다 65,498개 상품 전체 매핑을 다시 작성했다. 재개 중 뒤쪽의 기존 성공 자료도 임시 pending으로 표현될 수 있었다.
- 개선: JSONL 이력을 한 번 스트리밍으로 읽고 유효한 기존 성공을 전체 상태에 먼저 반영한다. 미처리·유실·오염 파일만 다운로드 큐에 넣는다. 캐시 URL을 journal에 다시 추가하지 않는다.
- `image_validation.jsonl`에 파일 경로·예상 SHA·크기·파일 ID·시각·레코드 체크섬을 보존한다. 그대로인 파일은 stat으로 재사용하고, 변경·유실·메모 손상 시 실제 SHA-256을 확인한다. Windows에는 creation time인 `st_ctime` 대신 NTFS ChangeTime도 포함한다. 지원하지 않는 파일시스템이나 파일 ID가 불명확하면 해시 검사로 돌아간다.
- 처음 적용할 때는 검증 메모를 구축해야 한다. 이후에도 URL별 가벼운 파일 상태 조회는 수행한다. 마지막 숫자 커서만 믿고 앞쪽 파일을 무조건 생략하는 방식이 아니다. 메모는 성능 캐시이며 전체 무결성 감사의 대체물이 아니다.
- `image_resume.json`, `download_report.json`은 경량 진행 기록이다. 원문 입력 SHA와 journal 위치를 기록하지만 저장 완료의 근거는 URL별 journal과 실제 파일이다. 강제 종료 후에도 남은 journal을 재사용한다.
- 전체 `products_with_local_images.jsonl`은 기본 **300초 간격** 및 종료·정상 인터럽트 때 저장한다. 캐시 준비 중 인터럽트가 오면 기존 전체 매핑을 덮어쓰지 않는다. URL별 결과는 계속 journal에 기록하므로 전체 매핑 저장 사이에 종료돼도 복구할 수 있다.
- 공유 blob·상품 파일명·URL·복수 카테고리 연결은 유지한다. 이미 같은 파일인 하드링크를 매번 다시 해시하지 않는다. 생성으로 ChangeTime이 바뀌면 파일 확인을 갱신한 뒤 매핑을 게시한다.
- 파일 기반 단일 작성자 잠금으로 같은 이미지 저장소의 동시 다운로드를 막는다. 프로세스 종료 시 OS 잠금은 해제되며 잠금 파일 존재만으로 실행 중이라고 판단하지 않는다. SQLite는 사용하지 않는다.
- 과거 실패는 기본 건너뛰고 `--retry-failed`로 명시 재시도한다. 새 실패에는 시각·run ID·시도 횟수·예외 종류·HTTP 상태를 기록한다. 403/429가 발생하면 해당 실행의 다음 요청을 중단한다.

## 실행 방법

프로젝트의 `src/commerce_crawler`에서 실행한다. 아래는 명령 안내이며 문서 작성 때 실행하지 않았다.

```powershell
..\..\.venv\Scripts\python.exe -m product_collector.media `
  --products data/danawa/0685b031-7662-45c6-bdfe-c7b499051069/products.jsonl `
  --output data/danawa/0685b031-7662-45c6-bdfe-c7b499051069/media `
  --interval 1 --timeout 20
```

- 실패 URL도 다시 시도: `--retry-failed`
- 기존 파일 전체 SHA 검사: `--verify-cache`
- 전체 매핑을 종료 시에만 저장: `--export-interval 0` (실시간 매핑 소비자는 종료까지 기존 스냅샷을 보게 됨)
- 소량 요청 한도: `--max-requests 5` (캐시는 재사용하고 실제 신규 요청만 제한)

PC 전용 실행기는 Git 배포 대상이 아니다. 다른 PC에서는 위 모듈 명령과 실제 수집 폴더를 사용한다. 폴더 이동 후에는 기존 실행기의 입력·출력 경로도 확인해야 한다. 현재 다운로드는 사용자 요청으로 중지했으며 이 변경을 반영해도 자동으로 재개되지 않는다.
