## 사용자 흐름과 화면

방 사진은 필수, 텍스트·스케치 중 하나 이상을 받는다. 새로운 품목 선택·실측 입력·배치 영역 지정 단계를 필수로 추가하지 않는다. 사진과 입력을 보존한 뒤 해석·검색하고 실제 상품을 바로 보여준다. 상품 카드의 선택 생성 버튼으로 배치 시안을 제공하며 추천 자체는 생성 없이 완료한다.

| 화면 | 제공 기능 |
|---|---|
| 입력 | 기존 업로드/Canvas 그리기·지우기·텍스트 입력과 수정, 추천 요청 |
| 해석·추천 | 원본 사진·배치 영역(확인된 경우), 해석된 요구·크기 근거/미확인 안내, 실제 상품 카드·가격/규격·추천 이유 |

## 추천과 크기 표시

사용자의 명시 조건과 방의 관찰 색상·스타일을 구분한다. 방이 갈색이라는 이유로 갈색 상품을 필수로 요구하지 않는다. 크기 basis는 VERIFIED_DIMENSION/TYPICAL_OBJECT_SIZE/RELATIVE_ONLY/NONE이며 코드가 실제 저장 참조를 대조한다. 지지되지 않는 축·단위는 미확인으로 두고 통상 치수 추정으로 필수 제외하지 않는다. 규격 누락은 조건 충족으로 표시하지 않고 크기 근거 부족만으로 전체 추천을 막지 않는다. 설치 가능·충돌 없음 보증은 제공하지 않는다.

## 데이터·운영·미구현 경계

신규 추천은 input_revision→recommendation_context→recommendation_run으로 연결하며 생성 실행/scene_object를 필수로 사용하지 않는다. 실제 데이터 필드·API v2·마이그레이션은 [직접 추천 계약](design/12-direct-recommendation.md)을 따라 별도 구현한다. 기존 링크·가격 스냅샷·UUID·Bronze·권한·보관/삭제와 로그 계약은 유지한다.

초기 추천은 라벨 없이 scikit-learn `cosine_similarity`와 수동 초기 가중치로 수행한다. `weighted-content-v1`은 선호 색상이 있으면 `0.85 × 유사도 + 0.15 × 색상 일치`, 없으면 유사도만 사용한다. 필수 조건 불일치는 제외하고 결측·미지원 필수 조건은 UNKNOWN 목록으로 분리한다. 가중치는 학습값이 아니며 점수는 확률이 아니다. 사람의 6만 이미지 전수 적합/부적합 라벨링·LogisticRegression 학습·직렬화 모델 파일은 초기 실행 조건이 아니다. 반응 자료를 충분히 확보한 뒤 지도학습을 별도 평가한다.

로컬 구현은 `src/interior_recommender/recommendation.py`와 `src/interior_recommender/web/direct.py`다. `python -m interior_recommender.web` 기본 경로가 직접 추천이며 기존 Canvas의 `POST /api/runs`를 재사용한다. 해석 1회와 질의 임베딩 1회를 기본으로 하며 성공 receipt를 재사용한다. 별도 입력 절차·템플릿 선택·이미지 생성은 없다. 실제 DB·Kafka·Delta Bronze·광고 서버 HTTP·FAISS·상품 링크 검증 API 통합 및 운영 배포는 아직 미구현이다. 논리 서비스 계약을 로컬 파일 구현 완료와 혼동하지 않는다.

전체 응답 시간은 대기/API/DB 포함 p95로 측정하며 전체 15초나 특정 동시 사용자 수를 보장하지 않는다.

# 3차 PRD: 템플릿 기반 공간 구성 및 실제 유사 상품 추천

- 상태: 검토용 초안 — 구현 완료를 뜻하지 않음
- 작성일: 2026-10-12
- 수정일: 2026-10-14 — 템플릿 생성·광고 서버 추천·다나와 연결 반영
- 기준 문서: [3차 BRD](BRD_3차.md)
- 운영 형태: 내부 비공개 시제품

## 1. 제품 목표와 핵심 원칙

사용자가 공간 사진 위에 스케치를 하거나 텍스트로 요구사항을 입력하면, 그 의도를 템플릿 기반 공간 구성으로 보여준다. 결과 속 물체를 선택하면 광고 서버를 통해 유사한 실제 상품을 추천하고 다나와로 연결한다.

- **공간 표현과 상품 추천을 구분한다.** 공간 구성은 템플릿을 활용하고, 실제 판매 상품 이미지를 공간에 직접 배치하지 않는다.
- **실제 상품과의 유사성을 안내한다.** 결과 속 물체와 추천 상품을 동일 제품으로 표현하지 않는다.
- **입력을 먼저 보존한다.** 스케치·텍스트를 인식 처리 전에 Bronze에 보존하며, 인식 실패로 원천을 삭제하지 않는다.
- **상품 노출 효과를 측정한다.** 추천을 통한 유사 광고 효과를 노출·선택·거절·판매 링크 클릭으로 평가하되 구매·매출로 해석하지 않는다.

이 문서에서 템플릿은 실제 판매 상품과 구분되는 공간 표현용 자료를 뜻한다. 사전 제작 이미지·형상 등 템플릿의 구체적인 형태와 적용 방식은 구현 전 확정한다.

## 2. 사용자와 이용 시나리오

### 내부 시험 사용자

1. 공간 사진을 파일 선택 또는 드래그 앤 드롭으로 업로드한다.
2. 사진 위에 원하는 위치·형태를 그리거나 텍스트로 요구사항을 입력한다.
3. 공간 구성 요청을 보내고 템플릿 기반 결과를 확인한다.
4. 결과의 물체를 선택하고, 잘못 분석된 품목·영역이 있으면 수정한다.
5. 유사한 실제 상품의 이미지·가격·규격을 비교한다.
6. 상품을 선택하거나 거절하고, 필요하면 입력 수정·재구성·재추천을 진행한다.
7. 광고 서버가 확인한 연결 주소로 다나와의 상품 정보를 확인한다. 확인된 직접 판매 링크는 별도 구매 버튼으로 제공할 수 있다.

스케치와 텍스트를 함께 입력하거나, 스케치 없이 텍스트만 입력할 수 있다. 공간 사진은 3차에서 필수이며, 스케치와 텍스트가 모두 비어 있으면 구성 요청을 보내지 않는다.

### 운영자

1. 상품정보·이미지의 수집, 제외, 중복, 실패 현황을 확인한다.
2. 공간 구성·물체 분석·검색·저장 작업의 상태와 실패 사유를 확인한다.
3. 실패한 작업을 재처리하고 이전 입력과 완료 결과가 유지되는지 확인한다.
4. 기간·상품·카테고리별 사용자 반응과 집계 반영 시각을 확인한다.

## 3. 제품 범위

### 포함 범위

- 사진 업로드, 사진 위 그리기·지우기·다시 그리기, 텍스트 입력·수정
- 스케치·텍스트 해석, 템플릿 기반 공간 구성, 물체 품목·영역 분석
- 물체 선택과 품목·영역 수정, 광고 서버의 실제 유사 상품 추천·비교·다나와 연결
- 결과·추천·선택 이력 저장과 판매 페이지 연결
- 사용자 입력·수정·요청·상품 반응 기록
- 인식 성공·실패 원천 보존과 Bronze → Silver → Gold 데이터 추적
- 수집·처리·재처리 상태 조회와 반응 집계

### 제외 범위

- 실제 판매 상품 이미지를 공간에 직접 합성·배치하는 기능
- 가구·인테리어 외 상품군 확장과 공간 사진 없는 탐색
- 배치 물체의 이동·크기 조절·복제와 조명·원근감·주변 사물 편집
- 대화형 에이전트를 통한 지속적인 조건 협상·자동 실행
- 유료 광고 계약·과금·입찰·수익 정산
- 내부 주문·결제·배송·반품 처리와 실제 설치 가능 여부 보증

현재 요구사항 입력과 수정은 3차에 포함한다. 대화형 에이전트 확장과는 구분한다. 별도 광고 서버가 추천과 상품 페이지 연결 대상을 결정하고 Application은 생성·화면·사용자 이력을 담당한다.

## 4. 화면별 제공 기능

## 5. 기능 요구사항과 인수 조건

FR-01~FR-10은 3차 필수 기능이다. 본문에서 선택 기능으로 표시한 직접 판매 링크와 추가 평가 범위는 핵심 다나와 연결과 구분한다. 인수 조건은 구현 후 충족 여부를 확인하는 기준이다.

### FR-01. 상품 원천 확보와 수집 대상 관리

- 확정된 대상 카테고리에서 다나와 상품정보·이미지를 확보해 실제 추천 후보를 준비한다. 이미지는 내부 저장소에 보존하고 상품과 연결한다. ABO는 별도 평가 자료로 관리한다.
- 원천 출처·상품번호·상품명·카테고리·이미지 참조와 다나와 연결 주소를 구분한다. 확인된 판매 조건에는 판매처·옵션·가격·배송·조회 시각을 연결한다.
- 상품정보 확보 방식은 추천 연결 대상과 독립적으로 정하고 원천과 처리 이력을 보존한다.
- 기존 도매꾹 이미지는 공간 표현용 AI 템플릿 제작 자료로 구분하며 추천 상품 이미지·인덱스와 혼합하지 않는다.
- 제공되지 않는 정보는 미제공 상태로 남긴다.
- BRD의 포함·제외·검토 대기 기준을 적용한다. 작은 의자·스툴은 크기만으로 제외하지 않는다.
- 제외·검토 대기 상품은 추천에 등록하지 않는다. 제외 대상으로 판정한 이미지의 신규 다운로드와 검색 등록을 막는다.
- 중복 판단 사유와 처리 결과를 기록하고, 추천 가능 여부를 원천 보존 여부와 구분한다.

**인수 조건:** 포함·제외·검토 대기 표본을 각각 검사한다. 상품 수·다운로드 성공 이미지 수·고유 이미지 수·추천 가능 상품 수를 따로 조회하고, 원천 상품번호와 이미지·판매 주소의 연결을 확인할 수 있어야 한다.

### FR-02. 공간 사진·스케치·텍스트 입력

- 파일 선택과 드래그 앤 드롭에 같은 파일 검증 기준을 적용한다. 지원 형식·용량·해상도 제한과 오류 사유를 안내한다.
- 사진 위 그리기·지우기·다시 그리기를 지원하고, 원본 사진·스케치·텍스트를 구분하여 보존한다.
- 스케치의 위치를 복원할 좌표 기준과 이미지 크기 정보를 저장한다. 화면 표시 크기가 바뀌어도 같은 공간 위치에 복원한다.
- 텍스트 입력·수정 완료 및 요청 제출 시점의 내용을 버전과 연결한다. 키 입력 하나마다 저장할 필요는 없다.
- 구성 요청에는 사진과 함께 스케치 또는 비어 있지 않은 텍스트가 필요하다.

**인수 조건:** 두 업로드 방식, 그리기·지우기·다시 그리기, 화면 크기 변경 후 복원, 텍스트 수정 이력 조회를 확인한다. 사진 없음·빈 입력·지원하지 않는 파일은 외부 처리 요청 전에 차단되어야 한다.

### FR-03. 입력 해석과 템플릿 기반 공간 구성

- 요청마다 사진·스케치·텍스트의 입력 버전을 고정하고, Bronze 보존이 확인된 후 해석·구성을 진행한다.
- 스케치의 품목·위치·형태와 텍스트 조건을 해석하여 템플릿 기반 결과를 제공한다.
- 추천 대상 실제 상품 이미지를 배치 재료로 사용하지 않는다. 사용한 템플릿과 입력·결과의 연결을 기록한다.
- 처리 중 상태를 안내하고 동일 요청의 중복 실행을 방지한다. 처리 중 입력을 수정하면 수정된 버전으로 별도 요청한다.
- 해석 불가·템플릿 부재·처리 실패는 원천과 실패 사유를 유지하고 수정·재시도를 안내한다.

**인수 조건:** 스케치+텍스트와 텍스트만 입력한 사례를 각각 수행한다. 결과의 템플릿·입력 버전을 조회하고, 인식 실패 스케치도 원천에서 확인할 수 있어야 한다. 템플릿 부재를 정상 구성 결과로 처리하지 않아야 한다.

생성 크기는 명시 조건을 우선하고 없으면 원본 주변 물체의 통상 치수 범위·가구 유형·원근으로 사진상 폭/높이의 하한·상한을 추정한다. 스케치 범위를 실측이나 고정 크기로 해석하지 않는다. 근거와 불확실성·입력/템플릿 버전을 고정하며 실제 상품 치수로 사용하지 않는다. [상세 크기 정책](design/11-scale-policy.md)을 따른다.

### FR-04. 물체 분석·선택·수정

- Gemini를 이용한 입력 해석·물체 분석 역할은 BRD를 따른다. 구체적인 모델과 요청 방식은 기술 설계에서 정한다.
- 구성 결과에서 물체의 품목과 영역을 제시하고 사용자가 검색할 물체를 선택할 수 있게 한다.
- 원본 사진과 구성 결과를 요청 조건·사용 템플릿 근거와 함께 비교해 기존 유지·추가·교체·구분 불확실을 표시한다. 이번 요청의 추가·교체 물체를 기본 추천 대상으로 삼고 기존 유지 물체는 제외한다.
- 불확실 물체는 사용자가 추가·교체 대상인지 확인하고 품목·영역을 확정하기 전에는 검색하지 않는다. 잘못된 구분도 수정할 수 있으며 분석 근거와 사용자 확인을 구분해 기록한다.
- 사용자는 잘못된 품목·영역을 수정할 수 있다. 원래 분석 결과와 수정 결과를 구분하여 저장한다.
- 물체를 찾지 못하거나 영역이 유효하지 않으면 전체 처리 성공으로 표시하지 않고 수정·재분석을 안내한다.

**인수 조건:** 기존 가구 유지, 빈 위치에 가구 추가, 기존 위치의 가구 교체, 구분 불확실 사례를 확인한다. 기존 유지와 확인 전 불확실 물체는 검색되지 않아야 한다. 사용자 확인·품목·영역 수정 후 대상 구분을 재검증하고 확정 크롭으로 검색하는지 확인한다. 조명·원근 변화만 있는 기존 가구를 신규 대상으로 자동 확정하지 않아야 한다. 텍스트만 입력한 경우에도 같은 구분·확인 규칙을 적용한다. 물체 없음·잘못된 영역·비교 분석 실패는 생성 결과를 보존하고 분석만 재시도할 수 있어야 한다.

크기 비교에서 과소·과대·혼합 범위 이탈·판단 보류를 구분한다. 원본 배경/카메라 변화, 낮은 근거, 계획/검사 누락은 적정으로 처리하지 않는다. 구조·주석·크기 검사를 모두 통과한 추가/교체 물체만 기본 추천 선택을 허용한다. 결과 보존 후 비교만 재시도하거나 새 요청으로 명시적 재생성을 수행하며 자동 재생성하지 않는다.

**추가 인수 조건:** 정상·과소·과대·깊이 차이·여백 변환·명시적 특수 크기·근거 부재·배경 변화·검사 누락을 확인한다. 비교 재시도는 생성 API를 호출하지 않아야 한다. 실제 시각 품질은 모의 코드 테스트와 별도로 평가한다.

### FR-05. 실제 유사 상품 추천·비교

- 광고 서버가 선택하거나 수정한 물체의 품목·영역을 기준으로, 미리 저장·임베딩한 다나와 상품 이미지의 서비스 인덱스에서 유사 후보를 찾고 검증된 다나와 상품 카탈로그로 순위를 결정한다.
- 품목 일치 여부와 시각적 유사성을 구분해 평가하고, 동일 상품이 중복 추천되지 않도록 한다.
- 원본 상품 이미지, 상품명, 판매처, 일반 판매가격·혜택가격 구분, 배송 조건, 규격, 조회 시각, 다나와 비교 주소와 확인된 구매 주소를 표시한다. 조건이 다른 가격을 동일 조건의 최저가로 비교하지 않는다. 없는 정보는 추정해서 채우지 않는다.
- ABO 시험 결과와 실제 다나와 상품 추천을 구분한다. 추천 이미지·상품명·가격·판매처·연결 주소는 같은 다나와 상품과 검증된 판매 조건에 근거한다. 도매꾹 이미지는 템플릿 제작 자료로만 관리한다.
- 결과 없음과 검색 실패를 구분한다. 유사 상품 추천이며 구성 결과와 동일 제품이 아니라는 점을 안내한다.

**인수 조건:** 품목 불일치·중복·제외 상품의 노출을 확인하고 확인된 다나와 연결 주소를 점검한다. 원천 이미지와 템플릿 기반 결과를 검색 입력으로 사용한 시험 결과를 따로 기록한다.

### FR-06. 결과 저장·상품 선택·판매 연결

- 사진·스케치·텍스트 버전·구성 결과·물체·추천 목록·선택 상품을 연결해 저장한다.
- 상품 선택과 명시적 거절을 구분하고 선택 카테고리를 기록한다. 선택하지 않은 상품을 자동 거절로 간주하지 않는다.
- 광고 서버가 추천 항목과 다나와 연결 주소의 대응을 확인하고 Application이 사용자 권한·클릭 기록 후 이동 응답을 제공한다. 검증된 직접 판매 링크는 선택 기능이며 비교 클릭과 구매 링크 클릭을 구분한다.
- 저장 실패 시 완료로 표시하지 않고 입력과 이미 완료된 결과를 유지하여 재시도를 지원한다.

**인수 조건:** 저장 결과를 다시 조회해 입력부터 선택 상품까지 연결을 확인한다. 선택 상품의 다나와 연결 대상과 클릭 기록이 일치하고, 저장 재시도로 이력이 중복 생성되지 않아야 한다.

### FR-07. 입력 수정·재구성·재추천

- 다시 그리기·지우기·텍스트 수정·다시 구성·품목/영역 수정·재추천·다른 상품 선택을 지원한다.
- 입력이나 검색 조건을 변경한 요청은 새 버전으로 기록하고 이전 요청과 연결한다.
- 같은 입력으로 실패 작업을 재시도하는 경우, 입력을 복제하지 않고 별도 실행 이력을 남긴다.
- 이전 성공 결과는 이후 실패로 삭제하거나 실패 결과로 덮어쓰지 않는다.

**인수 조건:** 인식 실패 후 텍스트 보완, 품목 수정 후 검색, 조회 실패 후 재시도, 결과 거절 후 재추천을 수행하고 전후 이력을 대조할 수 있어야 한다.

### FR-08. 행동 데이터와 실패 원천 보존

- 스케치·텍스트의 입력 내용과 수정 이력, 구성·추천 요청, 상품 노출·선택·명시적 거절·판매 링크 클릭을 기록한다.
- 행동마다 이벤트 식별자, 발생 시각, 세션 또는 허용된 사용자 식별자, 작업·입력 버전과 관련 상품을 연결한다.
- 스케치·텍스트 원천 내용은 보존 참조로 연결할 수 있으며, 모든 이벤트에 같은 원문을 반복 저장할 필요는 없다.
- 인식 실패 스케치와 관련 텍스트도 Bronze에 남기고 실패 상태·사유·처리 시각을 연결한다.
- 같은 이벤트의 재전달은 중복 집계하지 않는다. 사용자가 실제로 다시 실행한 행동은 새 이벤트로 구분한다.

**인수 조건:** 스케치·텍스트 수정 전후 버전과 인식 실패 입력을 조회할 수 있어야 한다. 이벤트 재전달 시험에서는 원래 반응 건수와 집계가 같아야 한다.

### FR-09. Bronze·Silver·Gold 연결과 반응 집계

- **Bronze:** 허용된 상품 원천과 사용자 사진·스케치·텍스트·행동 기록을 보존한다. 오류나 제외 판정으로 보존된 원천을 임의 삭제하지 않는다.
- **Silver:** 형식·단위·카테고리 표준화와 중복·결측·연결 검증을 수행한다. 실패·검토 대기 기록은 상태를 구분하고 정상 상품·정상 인식 결과로 승격하지 않는다.
- **Gold:** 서비스·광고 활용을 위한 추천·노출 정보와 기간·상품·카테고리별 반응 집계를 제공한다. 원천·정제 결과·집계 간 연결을 유지한다.
- 상품 노출은 목록에 실제 표시된 경우에 기록하며 검색 후보 생성만으로 노출을 집계하지 않는다.
- 집계는 노출·선택·명시적 거절·판매 링크 클릭 건수와 비율, 집계 반영 시각을 제공한다. 분모가 0이면 비율을 계산하지 않는다.

**인수 조건:** 표본 요청의 Bronze → Silver → Gold 연결과 단계별 건수·상태를 대조한다. 재처리·이벤트 재전달 후 중복 집계가 없어야 하며, 실패 입력은 정상 결과와 구분되어야 한다.

### FR-10. 작업 조회·재처리·운영 로그

- 수집·다운로드·입력 보존·구성·물체 분석·검색·결과 저장·정제·집계 작업의 시작·완료·실패와 재처리 상태를 조회한다.
- 실패 원인과 재시도 가능 여부를 안내하고 완료 작업의 중복 실행·적재를 방지한다.
- 원천 저장 실패는 입력을 보존한 것으로 표시하지 않는다. 원천 보존이 확인되기 전에는 후속 인식 처리를 진행하지 않는다.
- 재처리는 해당 실패 단계부터 수행하고 이전 완료 결과를 유지한다. 바뀐 입력은 재처리가 아니라 새 요청으로 구분한다.
- 운영자 기능은 허용된 내부 사용자만 접근할 수 있게 한다.

**인수 조건:** 단계별 실패를 재현하고 원천·완료 결과 유지와 재처리 상태를 확인한다. 작업 식별자로 애플리케이션·메시지 처리·분산 처리·DB 적재 로그를 추적하고 별도 보관 결과를 확인할 수 있어야 한다.

## 7. 오류·예외 대응

| 상황 | 사용자·운영자에게 제공할 동작 | 유지해야 할 데이터 |

| 사진 형식·용량 오류 또는 빈 입력 | 허용 조건 안내, 입력 수정 | 기존 정상 입력 |
| 원천 저장 실패 | 접수 실패 안내, 저장 재시도 | 현재 화면 입력과 기존 보존 원천 |

| 템플릿 없음 또는 구성 실패 | 지원 범위 안내, 입력 수정·재시도 | 요청 입력·이전 완료 결과 |

결과 없음·인식 불가·시스템 오류를 같은 실패로 표시하지 않는다. 실패 이유를 안내할 때 사용자 입력 원문이나 비밀정보를 운영 로그에 불필요하게 복제하지 않는다.

## 8. 비기능 요구사항

- **데이터 신뢰성:** 접수 입력과 허용된 수집 성공 데이터의 원천 보존 확인율 100%를 검증한다. 재전달·재시도·재처리로 반응·상품·결과가 중복 적재되지 않아야 한다.
- **입력 검증:** 업로드 파일과 입력값은 서비스 접수 단계에서 검증한다. 지원 범위를 벗어난 파일·잘못된 영역·누락된 필수 입력은 처리 전에 안내한다.
- **접근·보관 관리:** 내부 시험 사용자와 운영자 권한을 구분한다. 사진·스케치·텍스트의 외부 AI 전송, 이용 목적, 보관·삭제 기준을 안내하고 실패 원천에도 같은 정책을 적용한다.
- **상태 가시성:** 처리 중·완료·실패·재처리 중과 결과가 없는 상태를 구분한다. 운영자는 요청별 상태와 실패 단계를 추적할 수 있어야 한다.
- **측정 가능성:** 입력 보존·구성·분석·검색·저장·집계의 소요 시간과 실패 건수를 측정한다. 응답 시간·동시 사용자·집계 지연의 수치 목표는 시제품 측정 후 확정한다.
- **품질 평가:** 품목 일치율, 시각적 유사성 평가, 판매 주소 유효성, 입력 의도 반영 여부를 별도로 기록한다. 유사도 점수를 정확도 백분율로 표시하지 않는다.

## 9. 데이터 처리·운영 전제

현재 BRD의 역할 분리와 기존 기획의 공통 기술 전제를 함께 적용한다. 이 항목은 설계 기준이며 실제 구현 상태를 뜻하지 않는다.

- Django·HTML Canvas에서 사진·스케치·텍스트와 사용자 행동을 접수한다.
- MongoDB는 불변 상품 원천을, MySQL 입력 스냅샷·파일 저장소는 사용자 원문을 먼저 보존한다. Kafka로 참조·이벤트를 전달하고 Spark가 Delta Bronze에 복제한다. 사용자 입력의 Bronze 보존 확인 후 후속 인식·구성을 수행한다.
- Spark 분산 처리와 Parquet을 활용해 Silver 정제·검증 결과를 관리한다.
- MySQL에 서비스 조회·Gold 활용 데이터를 적재하여 Django의 추천·운영 조회에 제공한다. 세부 저장 위치·주기·테이블 계약은 기술 설계에서 정한다.
- Python Logging으로 애플리케이션·Kafka 처리·Spark·DB 적재의 운영 로그를 관리하고, AWS S3로 운영 로그를 이관·보존하는 기능을 구현한다.
- 별도 광고 서버가 추천과 링크 결정을 담당하는 방향은 채택한다. 실제 사양·배치·인증·시간 상한은 상세 설계와 배포 검증에서 확정한다.

## 12. 구현 전 확정 사항

다음은 BRD에서도 상세 설계에 맡긴 항목 또는 PRD 작성 시 수치·방식이 정해지지 않은 항목이다. 임의의 구현 완료 조건으로 취급하지 않는다.

- 템플릿의 형태·확보 방식·카테고리별 지원 범위와 공간 적용 방식
