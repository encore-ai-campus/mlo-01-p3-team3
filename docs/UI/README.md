## 재분류한 이유

작업 전 ver1 폴더는 비어 있었고 기존 원문 6개가 docs 최상위에 있었다. Git의 추적 경로에는 동일 파일명의 ver1 삭제와 최상위 미추적 파일이 함께 나타났다. ver2는 일부 8차 제목 아래에 9차 문단이 추가되어 현재 기능과 과거 설명이 섞여 있었다. 누가 왜 이동했는지는 파일 상태만으로 단정하지 않는다.

이번에는 원문을 ver1으로 모으고 ver2는 수정하지 않았다. ver3는 아래 주제별로 현재 상태를 다시 작성했다. 상세 이동표는 [문서 분류 및 업데이트 내역](ver3/05_이력/문서_분류및업데이트내역.md)에 있다. superpowers는 이미 설계/계획으로 분류된 원문이므로 경로를 유지했다.

## 문서 관리 기준

1. 최신 구현·정책은 ver3에 반영한다. 과거 버전 문장을 현재 설명처럼 덧붙이지 않는다.
2. 실제 기능 변경 차수, 문서 버전, Raw 스키마 버전을 구분한다.
3. 실제 구현·모의 기능·미구현·재검증 필요를 따로 표시한다.
4. 코드 변경 없이 문서만 정리한 작업을 기능 개발 실적으로 기록하지 않는다.
5. 새 문서는 목적에 맞는 폴더와 README 목차에 등록한다. docs 최상위에는 이 안내만 둔다.
