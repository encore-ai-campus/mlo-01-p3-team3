# RoomPick 선택 확장 구현 계획

기준은 기존 roompick이다. roompick_ver0.2는 참고 소스로만 사용하며 DB·환경·기존 문서를 복사하지 않는다. 사용자 요청에 따라 기존 도구 노출, 선택 편집, 결과 제목, 직접 가구 이동, 추천 이미지 세 칸의 위치를 유지한다.

## 구현 계약

- 홈·사진 선택/예시·사진 아래 업로드·설명(1,000자)/스타일(선택 1개)·그림 없이 생성·모바일 탭/고정 버튼을 확장한다.
- 입력은 통합 작업 이력에 포함하고 사진 교체/자르기에서도 유지한다. 스케치 수정은 이전 설명/스타일을 복원하고 새 사진/빈 스케치는 비운다.
- 공간 생성과 상품 추천을 분리한다. 결과에 배치 이력, 원본 비교, 품목/검색 영역 수정, 세 칸 추천/반응을 추가한다. 기존 결과에 없는 새 필드는 기본값으로 호환한다.
- 신규 업로드 원본/체크섬, 생성 입력, 추천 실행/재시도, 검색 조건 변경, 반응을 서버에 보관한다. 소유권/CSRF/중복 방지/버전 검증을 유지한다.
- 사진 입력과 무관한 기존 스케치 원본 스키마는 유지한다. 설명·스타일 및 반응은 서버 행동 이벤트와 생성 입력으로 수집한다.
- DB는 확장 migration만 적용한다. 작업 전 SQLite backup과 소스 보관을 수행하고 기존 ID/미디어를 보존한다. 실제 AI·판매 상품 연결은 계속 모의이다.

## 작업 분리

1. 서버: Python/config/migrations/tests. Project.request_context, Composition.generation_context/initial_placements; serialize(project).request_context; serialize_result은 참고 버전의 scene_objects/category_options/플랫폼 API 계약을 따른다. 원본·추천·검색 조건·버전/lease 경쟁 방어를 구현한다.
2. 결과 화면: result.html/result.mjs/전용 result-extension.css 및 테스트. 직접 드래그를 유지하고 서버 계약으로 추천한다. 배치 기록은 새로고침 후 유지하며 최초 배치는 서버 initial_placements를 따른다. 상품 세 슬롯을 보존한다.
3. 홈/편집/공통(주 작업자): editor.html/editor.mjs/home.html/home.mjs/editor-extension.css, events.mjs/API/공통 큐/브라우저 테스트. 기존 그리기/채우기/그룹/지우기 코드는 유지하며 입력과 사진 전환 이력을 통합한다.
4. 통합: Django·Node·격리 DB/미디어의 실제 PC/모바일 브라우저 검증, 별도 코드 검토, migration 보존 검증 후 기존 LAN 서버에 반영.
