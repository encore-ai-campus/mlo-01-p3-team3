# SketchOn 운영 콘솔 설계

사용자가 승인한 메뉴 제안을 구현한다. 경로는 /ops/, 대상 브랜치는 feature/#17, 운영 계정은 hilee다. 기존 비회원·회원 서비스와 Raw 원문을 보존한다.

- 8개 메뉴: 대시보드, 이용자, 작업/결과, 행동데이터, 수집 상태, 광고 운영, 광고 성과, 관리자 이력.
- 활성 staff와 페이지별 권한을 함께 검사한다. 원본 이미지/Raw는 민감자료 권한으로 별도 검사하며 열람과 변경은 감사 기록에 남긴다. hilee는 운영 그룹만 부여하고 superuser로 승격하지 않는다.
- 기존 데이터는 기존 기록으로 표시한다. 신규 Project에 흐름 ID를 전파하고 사건의 서버 수신 인증과 브라우저 보고 인증을 분리한다. 과거 자료의 발생 당시 회원 여부는 추정하지 않는다.
- 생성 요청 ID별 상태·종료·소요 시간을 기록한다. 재전송·동시 요청은 성공 기록을 실패로 덮어쓰지 않는다. 비회원 제한은 실패와 구분한다.
- Raw 원문은 불변이다. 수신/경고/재전송/검수 메타데이터만 별도 저장하며 기존 파일은 명시적 인덱싱으로 등록한다. 브라우저만 보관하는 미전송 자료는 서버에서 확인할 수 없음을 표시한다.
- 광고는 로컬 운영 초안이다. 소재·URL·품목·위치·집행 기간·가상 입찰과 운영자 승인/거절/중지를 구현한다. 소재 변경 시 재심사, revision으로 동시 변경 충돌을 막는다. 광고 서버 실적은 미연결로 표시하고 허위 성과·송출을 만들지 않는다.
- media_id=sketchon, slots=editor-right/result-right/my-right. Home/인증/운영 화면과 좁은 화면은 송출 대상에서 제외한다. 현재 실습 ad_server의 게임 계약·광고주 API를 직접 재사용하지 않는다.
- 날짜는 한국 시간, 목록은 필터/페이지 구분, 민감자료는 권한별 표시. 운영 화면에는 광고를 넣지 않는다.

완료 기준: 권한/CSRF/민감자료 접근, 생성 경합/실패 추적, Raw 재전송/원문 보존/검수, 광고 승인 및 수정 재심사/충돌, 8개 화면 PC/모바일과 기존 서비스 회귀 통과. DB·소스 백업 후 적용, 사용자 문서 이동은 보존한다.
