## 데이터 보존

실제 DB 백업: 프로젝트 옆 demo_sketchon-backups/2026-10-16-membership/db.sqlite3. source 폴더는 수정 전 소스, manifest.json은 기존 소스·미디어/Raw SHA-256, existing_ids.json은 기존 주요 테이블 PK 목록이다. 테스트 회원/프로젝트는 격리 DB에서만 만들며 실제 DB를 테스트 목적으로 초기화하지 않는다.


### 추가 확인 결과

- 기존 그림판 전체 흐름, Raw 임시 보관·재전송·복제 탭 보호, 5차 기능 확장, 7차 편집/결과 흐름, 추천 응답/이력 검사가 통과했다.
- 비회원 8건 동시 생성에서 3건 생성·5건 429. 한도 소진 후 같은 요청 재전송은 기존 결과를 반환하고 추가 차감하지 않았다.
- 같은 생성 request_id 8건은 결과 하나, 같은 프로젝트 저장 request_id 8건은 저장 버전 하나를 만들었다.
- 이 검사는 SQLite 개발 데모의 제한된 동시 요청 회귀이며 운영 처리량·AWS 성능 시험이 아니다.


### 최종 리뷰 수정과 재검증

사진 교체 시 저장 프로젝트 계보 유지, 계정 전환 시 미전송 Raw 보존·권한 재확인, 저장 대화상자 닫기·제목 초기화를 추가 검증했다. 세 문제를 먼저 재현한 뒤 수정해 통과했으며 전체 Django 87개·Node 26개를 다시 실행해 통과했다. 최종 브라우저 검사에서는 가입 완료 안내창 문구·1회 표시·자동 로그인·새로고침 미반복과 저장 버전 복원 후 사진 교체→재생성→같은 프로젝트 버전 2 저장까지 확인했다. 이전 계정의 늦은 추천 응답·이미지·열린 저장 대화상자는 새 계정에 노출되지 않았고, 이전 계정이 돌아오면 Raw가 전송됐다.

### 실제 폴더 적용 확인

검증된 소스를 C:\mlo-01-p3-team3\src\demo_sketchon에 반영하고 Django auth·sketch 0007 migration을 적용했다. 기존 작업 291·결과 71·이벤트 3,309·추천 7·물체 수정 9개의 PK를 보존했다. 기존 미디어·Raw·ver1 문서 210개 파일의 SHA-256이 동일하며 SQLite integrity_check는 ok였다. 검증용 회원은 실제 DB에 넣지 않았다.

실제 서버는 0.0.0.0:8003에서 실행하며 http://127.0.0.1:8003/ 와 http://192.168.0.44:8003/ 의 Home, LAN 로그인 페이지가 HTTP 200으로 응답했다. 현재 기본 경로의 DB·media·Raw를 사용한다. 백업 폴더는 .gitignore로 Git 추적에서 제외했다.

## 9차 실제 적용 확인

2026-10-16 `feature/#17`의 실제 데모에 migration 3개를 적용하고 기존 `hilee`에 운영자 그룹을 연결했다. superuser는 부여하지 않았고 비밀번호를 변경하지 않았다. 기존 Raw 42개를 읽기 전용으로 색인했으며 검증 오류는 없었다.

적용 전 존재하던 작업 337개·결과 77개·행동 이벤트 3,524개·추천 실행 10개·검색 조건 수정 9개·저장 프로젝트/버전 각 1개·찜 2개·회원 1개의 ID가 모두 유지됨을 확인했다. 사진·결과·Raw 등 기존 파일 236개의 SHA256도 일치한다. 실제 DB에 브라우저 테스트 계정은 만들지 않았다. 이후 정상 이용이나 접속 확인으로 데이터 수는 증가할 수 있다.

`http://127.0.0.1:8003/`와 `http://192.168.0.44:8003/`는 HTTP 200, 운영 CSS는 HTTP 200이다. 비회원의 `/ops/` 요청은 로그인으로 302 이동한다. 서버는 `0.0.0.0:8003`에서 실행한다. 운영자 로그인 후 상단 `운영 관리`로 접속한다. 실제 광고 서버는 시작하거나 연결하지 않았다.
