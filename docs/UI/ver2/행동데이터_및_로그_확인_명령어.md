## 3. 최근 행동과 종류별 집계

```powershell
.\.venv\Scripts\python.exe -B manage.py shell --no-imports -c "import json; from sketch.models import SketchEvent; rows=list(SketchEvent.objects.order_by('-event_time').values('event_id','event_type','event_time','project_id','payload')[:10]); print(json.dumps(rows,default=str,ensure_ascii=False,indent=2))"
```

```powershell
.\.venv\Scripts\python.exe -B manage.py shell --no-imports -c "from django.db.models import Count; from sketch.models import SketchEvent; rows=SketchEvent.objects.values('event_type').annotate(count=Count('event_id')).order_by('-count'); print(*[str(row) for row in rows],sep='\n')"
```

event_time은 서버 저장 시각이고 payload.client_time은 브라우저 기록 시각이다. 서버 이벤트에는 client_time이 없을 수 있다. UTC의 +00:00 출력은 KST와 9시간 차이가 난다. localtime으로 확인하려면 다음처럼 출력한다.

```powershell
.\.venv\Scripts\python.exe -B manage.py shell --no-imports -c "from django.utils.timezone import localtime; from sketch.models import SketchEvent; print(*[(e.event_type,localtime(e.event_time).isoformat()) for e in SketchEvent.objects.order_by('-event_time')[:5]],sep='\n')"
```

## 4. 조작하면서 자동 갱신

아래 루프만 Ctrl+C로 끝내면 된다. 서버 프로세스를 종료하는 명령이 아니다.

```powershell
while ($true) {
    Clear-Host
    .\.venv\Scripts\python.exe -B manage.py shell --no-imports -c "from sketch.models import SketchEvent; print('events:',SketchEvent.objects.count()); print(*list(SketchEvent.objects.order_by('-event_time').values('event_type','event_time','payload')[:5]),sep='\n')"
    Start-Sleep -Seconds 2
}
```

| 화면 조작 | 기대하는 기록 |
| --- | --- |
| Home 시작 | button.clicked(button=start-sketch) |
| 펜·지우개 선택 | tool.changed + 해당 버튼 clicked |
| 선 완료·취소 | stroke.completed / stroke.cancelled |
| 설명·스타일 변경 | requirements.changed / style.changed |
| 공간 만들기 성공 | search.clicked → search.completed → result.viewed |
| 가구 이동·수치 크기 조절 | result.moved/resized → result.adjusted |
| 결과 배치 Undo/Redo | 해당 button.clicked + 성공한 result.adjusted; 편집 history.undo와 구분 |
| 상품 찾기 | RecommendationRun의 상태와 items 확인 |
| 상품 반응 | PRODUCT_IMPRESSION / PRODUCT_SELECTED / PRODUCT_REJECTED |
| 검색 품목 변경 | SceneObjectRevision 확인 |
| 이미지 내려받기 | export.downloaded(format=png) |

## 6. 스케치 Raw JSON 확인

먼저 1절에서 실제 SKETCH_RAW_ROOT를 확인한다. 기본 경로를 쓰는 경우 다음을 실행한다.

```powershell
$sketchonRawPath = '.\data\sketch_raw'
if (Test-Path -LiteralPath $sketchonRawPath) {
    $sketchonRawFiles = @(Get-ChildItem -LiteralPath $sketchonRawPath -File -Filter *.json)
    "Raw JSON: $($sketchonRawFiles.Count)개"
    $sketchonRawFiles | Sort-Object LastWriteTime -Descending |
        Select-Object -First 5 Name, Length, LastWriteTime
} else {
    '이 경로에는 Raw 폴더가 없습니다. 저장 설정과 정상 제출 여부를 확인하세요.'
}
```

```powershell
$sketchonLatestRaw = Get-ChildItem -LiteralPath .\data\sketch_raw -File -Filter *.json -ErrorAction SilentlyContinue |
    Sort-Object LastWriteTime -Descending | Select-Object -First 1
if ($sketchonLatestRaw) {
    $sketchonSample = Get-Content -LiteralPath $sketchonLatestRaw.FullName -Raw -Encoding utf8 | ConvertFrom-Json
    $sketchonSample | Select-Object schema_version, sample_id, project_id, submission_reason,
        capture_status, duration_ms, undo_count, label_status, quality_status
    "Raw strokes: $(@($sketchonSample.strokes).Count)"
    "Operations: $(@($sketchonSample.operations).Count)"
    if (@($sketchonSample.strokes).Count -gt 0) {
        $sketchonSample.strokes[0].points | Select-Object -First 5 x,y,t,event_type,source,in_bounds,pressure
    }
    $sketchonSample.operations | Select-Object -Last 5 type,t,source_stroke_id,target_stroke_ids,target_item_ids
} else {
    '확인할 Raw JSON이 없습니다.'
}
```

quality_status=pending은 원본 계약상 고정값이며 저장 실패를 의미하지 않는다. pass/review는 API 응답이다. Raw 획이 0개여도 operation 기록이 있는 샘플일 수 있다. `-ErrorAction SilentlyContinue`는 권한 오류도 숨기므로 진단할 때는 이 옵션을 빼서 실제 오류를 확인한다.

## 7. 브라우저 저장소와 네트워크

현재 접속한 주소의 DevTools(F12)에서 확인한다. localhost와 내부망 IP는 서로 다른 origin이므로 같은 브라우저라도 localStorage·IndexedDB를 섞어 보지 않는다.

| 도구·위치 | 확인 항목 |
| --- | --- |
| Application → IndexedDB → roompick-sketch-v1 | drafts: 작성 중/미확정, outbox: 미확인 제출, failed: 검토 필요 오류 |
| Application → Local Storage | roompick.events.* 및 roompick.product-events.*의 pending/rejected |
| Application → Session Storage | roompick.history.*, roompick.placement-history.*, 추천 요청 참조 |
| Network → events/samples | 요청 상태와 응답 본문, 재전송 ID가 같은지 |
| Network → scene-generations/recommendations/revisions | 생성·추천·조건 수정의 별도 요청 |
| Console·화면 수집 상태 | JS 오류·저장 실패·Raw 한도·미제출 안내 |

일반 LAN HTTP에서 Raw 초안 자동 복구는 Web Locks 부재로 제한될 수 있다. 정상 종료 outbox 전송과 편집 sessionStorage 복원은 별도 기능이다. pending/outbox가 남으면 성공 응답 여부를 확인하고, 원본 JSON을 임의 편집해 같은 sample_id로 다시 보내지 않는다.

## 9. 이벤트 내보내기: 파일을 만드는 선택 명령

전체 사건을 콘솔에 출력만 하려면:

```powershell
.\.venv\Scripts\python.exe -B manage.py export_sketch_events
```

NDJSON 파일로 보관하려면:

```powershell
.\.venv\Scripts\python.exe -B manage.py export_sketch_events |
    Set-Content -LiteralPath .\sketch-events.ndjson -Encoding utf8
```

특정 작업만 출력하려면 실제 UUID로 바꾼다.

```powershell
.\.venv\Scripts\python.exe -B manage.py export_sketch_events --project '실제-작업-UUID'
```

이 명령은 SketchEvent를 읽어 출력할 뿐 `published_at`을 바꾸거나 Kafka 메시지를 발행하거나 consumer offset을 변경하지 않는다. 출력 파일에는 스케치·설명과 익명 ID가 포함될 수 있다.

## 10. 새 서버 실행과 로그 보관: 필요할 때만

이미 같은 포트에 서버가 실행 중이면 해당 실행 터미널에서 먼저 종료한다. 다른 프로세스를 임의로 종료하지 않는다. 아래는 새 경로에서 서버를 실행하고 로그 파일을 만드는 예시이며 기존 프로세스 상태를 확인하는 조회 명령이 아니다.

```powershell
Set-Location C:\mlo-01-p3-team3\src\demo_sketchon
.\.venv\Scripts\python.exe -B -u manage.py runserver 0.0.0.0:8003 --noreload 2>&1 |
    Tee-Object -FilePath .\sketchon-server.log
```

다른 터미널에서 `Get-Content -LiteralPath .\sketchon-server.log -Tail 30 -Wait`로 확인한다. 이 방식의 파일 이름은 data/runtime의 기존 분리 로그와 다르다. --noreload는 템플릿·Python 변경 후 직접 재시작해야 한다. 내부망 IP·방화벽 설정은 [README](../../README.md)를 참고한다.

## 11. 확인 결과를 남기는 기준

조회 시각·사용한 DB/RAW 경로·대상 ID·응답 상태를 함께 적는다. 사진 선택 이벤트와 실제 업로드 성공, 생성 성공과 Raw 제출 성공, API 성공과 다운로드 파일 저장 완료를 구분한다. 이번 ver2 작성에서는 읽기 전용 개수·스키마 확인과 문서 검사를 수행했으며 서버·전체 기능 테스트를 새로 실행하지 않았다.
