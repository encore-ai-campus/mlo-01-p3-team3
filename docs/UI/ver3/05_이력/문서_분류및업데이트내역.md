# 문서 분류 및 업데이트 내역

기준일 2026-10-18 · 서비스 기능 변경이 아닌 문서 작업 기록이다. [최상위 안내](../../README.md), [ver3 목차](../README.md).

## 1. 작업 전 상태와 원인으로 확인한 것

docs에는 ver1·ver2·superpowers 폴더와 원문 6개가 섞여 있었다. ver1은 비어 있었고 Git에는 ver1의 해당 6개 파일 삭제와 docs 최상위의 동명 미추적 파일이 함께 보였다. 이는 파일 위치가 버전 분류와 어긋난 상태였다는 증거이며, 누가 어떤 의도로 이동했는지는 추정하지 않았다.

ver2는 여러 구현 차수를 반영하는 과정에서 8차 제목/설명과 9차 문단이 한 문서 안에 공존했다. 이를 새 현재판에서 그대로 누적하기보다 ver3에 현재 상태를 주제별로 다시 작성했다.

## 2. 분류 원칙

- docs/README.md: 현재판과 보존판을 고르는 단일 진입점
- ver1: 초기 원문 6개 보존. 본문 변경 없이 이동
- ver2: 2026-10-16 문서 13개 그대로 보존
- ver3: 현재 작업현황과 5개 주제 폴더의 문서 14개
- superpowers/specs·plans: 이미 분류된 설계/계획 원문 5개. 기존 경로 유지
- 프로젝트 README: 최신 문서 링크를 ver3로 연결. 서비스 코드/데이터와 별도

이제 docs 최상위에는 README만 남기고 새 주제 문서를 흩어 놓지 않는다. 버전 폴더 아래에서 현재 정책과 역사 기록을 섞어 현재 완료 범위를 오해하게 하지 않는다.

## 6. 보존과 검증 기준

적용 전 문서·README를 작업 백업에 보관한다. 이전 docs 전체 파일 수/해시를 기준으로 ver1 이동 6개와 ver2/설계 18개 내용이 모두 같은지 검사한다. 서비스 코드·테스트·설정·DB·media·Raw는 이 문서 적용의 쓰기 대상이 아니다. 현재판과 안내의 Markdown 링크는 재배치 후 실제 경로로 검사한다. 역사 원문의 오래된 링크는 원문 보존과 별도로 보고한다.

이번에 재실행한 것은 Django 기본 검사·기존 테스트와 Node 테스트다. 브라우저/실기기·LAN/서버 재시작·실제 광고·AWS·부하/복구 검증은 수행하지 않았다. 테스트 1건은 날짜 의존으로 실패했고 수정 대상으로 남겼다.
