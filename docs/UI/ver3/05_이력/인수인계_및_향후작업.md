# 인수인계 및 향후 작업

기준일 2026-10-18 · 이 문서는 구현 완료를 선언하는 로드맵이 아니라 현재 코드의 경계와 다음 작업 목록이다.

## 1. 유지해야 할 결정

- 기준 구현은 기존 roompick의 편집/수집 기능이며 참고 버전의 일부 UI/흐름을 덧붙여 확장했다. 현재 위치는 demo_sketchon이고 표시명/로고는 Sketch · On이다.
- 브라우저 방문 ID를 새로고침·다시 그리기 때문에 바꾸지 않는다. 계정 연결 시 owner/Raw는 유지하고 미귀속 account만 연결한다.
- 회원 저장은 프로젝트의 새 버전 추가다. 이전 결과를 덮어쓰지 않는다. 사진 교체/재시작 때 이 계보를 불필요하게 끊지 않는다.
- 모든 스케치는 하나의 원하는 가구 입력으로 취급한다. 펜 획마다 가구를 생성하지 않는다.
- 선택/채우기/지우기/그룹은 편집 요소의 관계를 지킨다. 내부의 독립 도형/획은 그룹 전 임의로 묶지 않는다.
- 실제 AI/상품/광고가 없을 때 결과를 예시/미연결로 표시한다. 임의 가격/CTR/매출을 만들지 않는다.
- 상품 추천 카드와 광고 배너는 구분한다. 현재 광고 서버 개발 전 로컬 초안만 검증한다.
- Raw의 점별 시간·작업 이력과 최종 문서는 따로 보존한다. 원문을 검수용으로 다시 쓰지 않는다.

## 2. 먼저 처리할 항목

| 항목 | 현재 근거/상태 | 다음 작업 |
| --- | --- | --- |
| 날짜 의존 테스트 | test_quota 마지막 조회가 mock 범위 밖, 이번 1건 실패 | 테스트 시각을 통제하고 106개 전체 재검증 |
| Git 반영 | feature/#17 작업 트리에 운영 앱·0008·ops 테스트 미추적, 기존 수정 파일 존재 | 실제 변경을 검토해 추적/커밋하고 팀원이 같은 상태를 재현하도록 공유 |
| 문서 유지 | ver3가 현재판, ver1/ver2/설계는 역사 원문 | 기능 변경 시 현재 현황·페이지·API·데이터 문서와 근거 갱신 |

이번 문서 작업은 커밋/푸시·기능 수정·테스트 수정·DB 마이그레이션·서비스 재시작을 수행하지 않는다.

## 3. 실제 생성/추천 연결

현재 scene-generation 경로는 mock search를 호출한다. 추천 provider 교체 지점은 존재하지만 실제 상품 검색/FAISS 서버가 연결된 것은 아니다. 먼저 입력 사진/문서/설명의 revision, 작업 ID, 생성·객체·추천 응답, 오류·취소·재전송·timeout 계약을 확정해야 한다.

장기 작업으로 바꿀 경우 요청 접수와 입력 보존, durable job 상태, worker lease/재처리, 결과 저장/사용량 차감, 오래된 결과 응답 폐기를 함께 설계한다. 기존 GET job 조회나 추천 lease만으로 큐가 완성됐다고 판단하지 않는다. 제공자 자격증명은 브라우저에 보내지 않는다.

실상품 연결 시 안정 product ID·카탈로그 출처·실제 가격/사양·링크 허용 범위·찜과 비교 snapshot 규칙이 필요하다. 사용자가 고친 검색 품목과 모델의 분류/정답 라벨을 구분한다.

## 4. 광고와 개인화

광고 서버가 없는 지금은 로컬 초안/심사만 유지한다. 다음에는 운영자/광고주/매체 권한, 금지/허용 품목·착륙 페이지·소재 정책, 승인 무효화, 기간/활성/품목 적합 필터와 가상/실제 입찰을 분리한다. 실제 표시 결정과 노출/클릭 ID, 중복 처리, 실패 시 fallback, 성과 정의가 필요하다.

개인 맞춤 광고는 개인 이력이 쌓인다는 이유만으로 실행하지 않는다. 동의/목적·보관·삭제·외부 전달 필드를 정한 뒤 연동한다. 매출/정산·CPC/CPM·예산 소진은 현재 범위 밖이다. [관리자/연동 설계](../04_운영/관리자_페이지_이용및연동설계.md)를 참조한다.
