## 2. 화면과 접근 범위

일반/회원 화면은 Home, 편집, 결과, 로그인, 회원가입, 회원정보, 찜 목록, 프로젝트 목록, 프로젝트 상세, 이미지 비교가 있다. 편집은 새 작업/기존 작업 URL을 함께 사용한다. 운영 콘솔에는 운영 개요·이용자·작업/결과·행동 데이터·스케치 수집·광고 관리·광고 성과·감사 이력과 작업 상세/광고 초안 폼이 있다.

비회원은 본인 브라우저의 미귀속 작업만, 회원은 자신의 계정에 연결된 작업만 접근한다. 개인 이력과 찜 버튼은 회원 전용이다. 운영자는 활성 staff와 메뉴별 권한이 필요하고 사진/Raw에는 민감 원본 권한을 별도로 검사한다. [페이지별 상세](01_서비스/페이지_기능구현범위.md), [운영 권한](04_운영/관리자_페이지_이용및연동설계.md)을 참조한다.

## 3. 구현됐지만 완성으로 오해하면 안 되는 항목

1. 모의 품목은 텍스트 키워드·예시 규칙과 스케치 경계로 정한다. 그림 의미를 AI가 이해한 결과가 아니다. 기본 예시가 화분으로 나와도 인식 정확도를 측정한 것이 아니다.
2. 추천 카드에는 실제 판매 가격·상품 ID·구매 링크가 없다. 추천 반응 이벤트와 광고 노출/클릭 실적은 서로 다르다.
3. 결과 사진의 크기는 **전처리/자르기 후 공간 사진**과 같다. 원본 업로드가 2,048px보다 크면 축소되므로 업로드 원본 픽셀 수와 결과 픽셀 수가 항상 같은 것은 아니다.
4. `api/jobs`와 RUNNING/FAILED 상태가 있어도 별도 생성 워커·Celery·영속 큐가 구현됐다는 뜻은 아니다. 현재 생성은 요청 안에서 실행하는 모의 처리이고 job 조회는 추천 실행의 상태 계약이다.
5. Raw 파일/행동 기록이 있다고 학습 라벨·개인정보 동의·광고 개인화가 완료된 것은 아니다. 자동 검증과 사람 검수도 별도다.
6. 트랜잭션·중복 방지·소규모 동시 요청 검증은 존재하지만 운영 규모의 성능·가용성 보장은 별도다.
