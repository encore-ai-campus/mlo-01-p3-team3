## 2. 날짜 의존 실패 한 건

`sketch.test_quota.QuotaTests.test_midnight_kst_and_untrusted_forwarded_ip`의 마지막 assertion이 `0 != 1`로 실패했다. [test_quota.py](../../../sketch/test_quota.py)의 2026-10-16 14:59:59/15:00 UTC를 mock한 블록에서 KST 10월 16/17일 사용량을 만든다. 마지막 요청은 mock 범위 밖이라 실제 10월 18일의 오늘 한도를 조회한다. [quota.py](../../../sketch/quota.py)는 오늘 날짜 기준이므로 0을 반환한다.

판정은 **날짜에 의존하는 테스트 결함**이다. 이것만으로 실제 IP 제한 기능이 고장 났다고 결론 내리거나 전체 106개 통과로 기록하지 않는다. 수정 방향은 마지막 조회까지 동일 시간 mock을 유지하거나 현재 날짜 기준 상대 시각을 만드는 것이다. 이번 문서 작업에서는 수정하지 않았다.

## 3. 과거 검증과 구분

2026-10-16 ver2 기록에는 Django 106개·Node 26개, Edge 운영 8개 메뉴·보호된 스케치·광고 등록/승인/재심사·모바일·로그아웃/뒤로가기 검증과 회원/배너 회귀 결과가 있다. 동시 요청 8건에서 비회원 성공 3/제한 5, 동일 생성 요청은 결과 1, 동일 저장 요청은 버전 1을 확인한 기록도 있다.

이는 당시 기록이다. 이번 테스트 실패는 실제 날짜가 달라져 드러난 것으로, 과거 기록을 삭제하거나 이번 날짜의 전체 통과로 바꾸지 않는다. 원문은 [ver2 검증 기록](../../ver2/문서_업데이트_요약.md)에 있다.

## 5. 재검증 방법과 주의

기존 venv와 설치된 Node를 사용한다. 테스트에서는 `ROOMPICK_DB_PATH`, `ROOMPICK_MEDIA_ROOT`, `ROOMPICK_RAW_ROOT`를 실제 업무 경로와 분리해야 한다. 기존 브라우저 동시성 스크립트는 당일 비회원 quota가 비어 있는 격리 DB를 전제하므로 이미 3회 사용한 DB에 재실행한 429를 새로운 회귀로 오해하지 않는다. 검증을 위해 실제 사용자 한도를 초기화하지 않는다.
