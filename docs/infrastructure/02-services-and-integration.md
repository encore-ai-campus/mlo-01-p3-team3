# 서비스 구축과 업무 통합의 경계

[문서 목록](README.md) · 근거: [E05](07-evidence-and-handoff.md#e05), [E09](07-evidence-and-handoff.md#e09), [E13](07-evidence-and-handoff.md#e13)

## Kafka

Kafka 4.1.2의 3노드 KRaft 브로커·컨트롤러를 구성했다. 동일 클러스터 ID, 3개 voter·broker 상태를 확인하고 mTLS·ACL을 유지한 상태에서 실제 메시지를 생산·소비했다. NiFi의 트랜잭션 메시지 송신도 검증했다.

최초 포맷은 비어 있고 프로젝트 전용임을 확인한 신규 저장소에만 허용했다. 기존 클러스터 ID 재생성·기존 로그 삭제는 복구 방법으로 사용하지 않는다. Kafka 정상 응답만으로 업무 이벤트 계약·재처리·지연 목표 달성을 선언하지 않는다.

## Spark

Spark 4.1.3 Master 1대와 Worker 3대의 등록, 인증·암호화된 RPC, 보호된 관리 화면을 확인했다. SparkPi 및 실제 분산 SQL Job이 성공했다. S3A는 후속 Garage 시험에서 실제 Worker를 포함해 검증했다.

원래 통합 조사 시 팀 클라이언트 버전 차이가 이슈였다. 이후 확인한 dev 기준 코드에는 서버용 PySpark 4.1.3·delta-spark 4.4.1 고정과 역할별 의존성 파일이 있다. 이는 최신 코드의 정적 확인이며, 이 문서 작업에서 설치하거나 모든 팀원 환경을 재검증한 것은 아니다.

## NiFi

NiFi 2.12.0은 약 3.3 GiB VM에 맞춰 JVM heap 512 MiB~1 GiB로 구성했다. TLS·로그인 인증을 유지했고 인증된 HTTPS API, GenerateFlowFile → PutFile 바이트 일치, Kafka 트랜잭션 송신을 확인했다.

Garage 구축 후 실제 S3 프로세서의 업로드·조회·파일 비교·삭제도 성공했다. 시험용 프로세서는 종료하고 활성 스레드가 남지 않았음을 확인했다. 이러한 시험 결과는 팀원 업무 파이프라인을 임의 수정했다는 의미가 아니다.

## MySQL 직접 접속 이슈

인프라 통합 조사에서는 NiFi의 MySQL 연결이 TCP 이후 오류 1130으로 거절됐다. 비밀번호 검증 이전의 접속 호스트 허용 문제였고 해당 출발지용 업무 계정·DB·권한 계약이 확인되지 않았다.

기존 계정 범위를 넓히거나 모든 호스트 허용 권한을 부여하지 않았다. DB 담당자가 승인한 실제 대상·작업 범위에 따른 최소 권한과 TLS 연결 검증이 남았다. 이후 팀원의 임시 스키마·Unix socket 계약 시험은 직접 네트워크 TLS 연결 해결의 증거로 대체하지 않는다.

## Django와 시험 E2E

Django 6.1.2·Gunicorn 26.2.0은 인프라 시험 애플리케이션이다. HTTPS 요청과 MySQL 연결을 확인했지만 실제 상품 추천·로그인·관리자 화면 등 팀 업무 애플리케이션의 완성을 뜻하지 않는다.

Stage 3 시험은 NiFi → Kafka → Spark SQL → MySQL 시험 데이터 → Django 조회의 연결을 확인했다. 1,000개 레코드 합계 499,500과 단계 간 해시를 대조했다. 일부 구간은 일회성 오케스트레이션이므로 지속 실행되는 업무 파이프라인이라고 기록하지 않는다.

## 팀원의 후속 검증과 미완료 범위

2026-10-18 팀 파이프라인 문서는 상품 3개·이미지 9개의 MongoDB → Garage → Kafka → Bronze 처리, 반복 실행 멱등성, Worker 3대의 Delta 작업을 보고한다. Silver·Gold 일부 결과는 QUALITY_WAIT이며 추천 준비 완료 상태가 아니다.

동일 문서는 MongoDB majority·journal 쓰기, 3노드 majority 읽기와 lease 동작을 별도 시험 데이터로 검증했다고 보고한다. 이는 **팀 파이프라인 담당자의 인증 시험 기록**이다. 신성민의 기존 인프라 검증에서 보류된 인증 계정·권한·전체 운영 검증을 소급해 완료 처리하지 않는다.

임시 MySQL 계약 시험과 NiFi의 제한된 실행 트리거 시험 역시 전체 업무 DB 게시·외부 입력부터 추천 화면까지의 E2E 완료와 구분한다. 후속 팀 문서·코드의 정확한 기준 commit은 [E13](07-evidence-and-handoff.md#e13)에 연결했다.

추가 인수인계는 실제 업무 DB 권한 승인, 팀원별 클라이언트 인증서·CA 전달, 역할별 가상환경 설치, 업무 E2E 재현·운영 책임 확정이다. 인증서를 신뢰하지 않도록 우회하거나 파이프라인 코드를 무단 수정하지 않는다.
