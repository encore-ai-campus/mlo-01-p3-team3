# VMware 인벤토리와 AWS 이전 준비

[문서 목록](README.md) · 근거: [E11](07-evidence-and-handoff.md#e11), [E12](07-evidence-and-handoff.md#e12)

## 확인한 원본

2026-10-18 Windows 5대에서 VM 20대·가상 디스크 28개를 식별했다. 실제 guest 네트워크 정보·VMX NIC·SCSI 위치·용량을 대조하고 VMDK parent CID·extent 존재·체인을 검사했다.

| 호스트 구분 | VM 수 | 디스크 수 |
|---|---:|---:|
| A | 4 | 5 |
| B | 4 | 5 |
| C | 4 | 7 |
| D | 4 | 5 |
| E | 4 | 6 |
| 합계 | 20 | 28 |

OS 디스크 20×40 GiB, DB 추가 6×50 GiB, 객체 저장소 추가 2×100 GiB로 총 가상 용량은 1,300 GiB다. 수집 당시 활성 디스크 체인 할당량은 약 205.965 GiB였다. 이는 최종 OVA 크기나 guest 파일 사용량이 아니다.

20대 모두 실행 중이었고 OS 디스크에 snapshot chain이 있었다. **추가 데이터 디스크 8개는 기존 snapshot 목록에 포함되지 않았다.** OS snapshot만 복원해 DB·Garage 일관성을 복구할 수 있다고 가정하지 않는다.

Bastion 1대는 BIOS, 나머지 19대는 UEFI였다. 일부 전체 디렉터리 탐색에는 시간 제한·접근 제한이 있었지만 대상 20대는 별도 대조로 모두 식별했다. PC 안의 모든 숨겨진 VM까지 조사 완료했다고 주장하지 않는다.

## 시험 대상과 이미지 정합성

Ad Server가 첫 시험 후보다. 실제 원본 VMX·40 GiB OS 디스크·snapshot chain을 찾았고 OVF Tool 존재를 확인했다. 경로는 공개하지 않으며 보호된 호스트별 목록을 사용한다.

원본이 실행 중이고 종료·snapshot 변경 승인이 없으므로 아직 OVA를 만들지 않았다. 실행 중 VMDK 파일 복사본을 일관된 정상 이미지로 취급하지 않는다.

가능한 다음 단계는 검증된 종료 상태 백업 사용 또는 별도 유지보수 승인 후 일관된 복제본 확보다. 그 전까지 내보내기·변환은 보류한다. 원본은 보존하고 복제본에만 네트워크·인증·부팅 준비를 적용한다.

VM에서 ENA·NVMe 및 initramfs 구성을 조사했지만 이것만으로 AWS 부팅 성공이나 VM Import/Export 지원을 확정하지 않는다. Ubuntu 26.04·실제 커널·UEFI·선택 인스턴스 지원은 실행 직전 공식 지원표와 해당 AWS 계정의 조회 결과를 다시 확인해야 한다.

VM Import/Export와 AWS Application Migration Service는 다른 경로다. 당시 조사한 MGN 지원 목록에 26.04가 없다는 결과를 VM Import/Export 지원 판정으로 대체하지 않는다.

## AWS 인증·리소스 상태

Windows 중앙 PC에는 AWS CLI v2 2.38.1을 설치하고 공식 서명을 확인했다. 중앙 CLI의 인증 프로필은 아직 학원 정책에 따른 설정이 필요하다. IAM Access Key를 임의 생성하거나 팀원에게 배포하지 않았다.

사용자가 CloudShell에서 확인해 전달한 결과는 STS 성공, 서울 리전 조회 성공, VPC 0·Subnet 0·S3 bucket 0·vmimport 역할 없음이다. IAM 사용자에 AdministratorAccess가 직접 연결됐다는 결과도 사용자 제공 증거다. 문서 작성자가 CloudShell을 직접 실행한 것으로 표현하지 않는다.

관리자 정책 연결만으로 조직 정책·permission boundary·학원 사용 제한·비용 승인이 모두 확인된 것은 아니다. 계정 ID·사용자 이름·자격증명은 공개 문서에서 제외한다.

## 준비된 실행 순서와 승인 관문

| 순서 | 준비 내용 | 실행 전 조건 |
|---|---|---|
| 1 | 안전한 복제본과 전체 디스크 manifest 확보 | 일관성 백업·중단 조건 승인 |
| 2 | 복제본에서 OVA 생성·SHA256·필요 공간 확인 | 모든 extent 포함, 원본 파일 변경 없음 |
| 3 | 비공개 S3 import 저장소 준비 | 계정 정책·암호화·접근 제한·비용 승인 |
| 4 | vmimport 역할·신뢰·최소 권한 정책 구성 | IAM 권한·S3 범위·정책 검토 |
| 5 | VPC·Subnet·route·보안 그룹 설계 적용 | 기존망과 주소 충돌 방지, 네트워크 승인 |
| 6 | 업로드·Import Image·변환 상태 확인 | 정확한 이미지 해시·지원 형식 검증 |
| 7 | 격리된 EC2·EBS 시험 부팅 | 유료 생성 승인, 이미지·인스턴스 호환 |
| 8 | SSH·DHCP·스토리지·guest 상태 점검 | 최소 출발지 허용, 온프레미스 통신 격리 |
| 9 | 별도 AWS 인벤토리·인증서·서비스 주소 계획 | 기존 클러스터에 자동 합류하지 않음 |
| 10 | 시험 결과 보존·임시 자원 정리 | 공유 자원 영향·삭제 대상 확인 |

VPC·Subnet·S3·vmimport가 없다는 조사 결과를 반영한 bootstrap 절차와 정책 초안은 보호된 준비 자료에 있다. 이 PR에는 그 스크립트를 올리지 않는다.

이미지에는 SSH·Vault·인증서·클러스터 식별정보가 포함될 수 있다. 복제본의 접근권한을 제한하고 온프레미스와 통신할 수 없는 격리 환경에서 시험한다. 기존 고정 IP·NIC 기준 설정은 복제본에서만 검토하며 원본 VM을 변경하지 않는다.

## 비용·복구·미완료 조건

기존 준비 문서의 24시간 소규모 시험 추정치는 약 USD 1.35이며 EC2·EBS·S3·snapshot 가정에 따른 과거 예시다. 네트워크 전송·KMS·세금 등을 제외했고 최신 견적·상한·학원 허용 한도를 검증한 금액이 아니다. 인스턴스 유형·가격은 지원 확인 후 다시 산정한다.

원본 호스트의 복제·내보내기 공간과 중앙 PC 수신 공간을 따로 확보해야 한다. 가상 디스크 용량·할당량만으로 압축률이나 필요한 peak 작업 공간을 확정하지 않는다.

실패 시 import task 상태를 확인하고 임시 업로드·AMI·snapshot·EC2·EBS·네트워크·IAM 자원을 소유 태그·의존성 기준으로 정리한다. 실행 중인 원본과 기존 공유 자원은 삭제하지 않는다. 자동 정리 초안은 아직 실환경 정리 성공의 증거가 아니다.

**현재 실제 이전 차단 조건**은 일관된 이미지 미확보, 학원 정책에 맞는 CLI 인증·권한 확인, VM Import/Export 지원 최종 확인, 신규 네트워크·S3·역할 및 유료 시험 승인이다. OVA·AMI·EC2 생성이나 실제 AWS 마이그레이션은 완료하지 않았다.
