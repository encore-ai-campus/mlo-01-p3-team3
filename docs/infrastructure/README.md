# PJ3 인프라 구축·운영 기록

작성: 신성민 · 기록 기준: 2026-10-17~18 · 문서 작성: 2026-10-18

## 구축 상태 요약

| 영역 | 마지막으로 확인한 결과 | 제한 |
|---|---|---|
| 플랫폼·패키지 | VM 20대 승인 패키지 검증 | 패키지 설치와 전체 서비스 완성을 구분 |
| Kafka | 3노드 KRaft 및 실제 생산·소비 검증 | 업무 이벤트 전체 흐름의 완료 증거는 아님 |
| Spark | Master 1·Worker 3, 실제 Job 성공 | 팀 애플리케이션 의존성은 별도 검증 |
| NiFi | 인증된 HTTPS·Kafka·S3 시험 성공 | 실제 업무 DB 직접 접속은 미해결 기록 존재 |
| MySQL | Primary 1·Replica 2, GTID·TLS·복제 검증 | 자동 장애조치 미구현 |
| MongoDB | 기존 3노드 Replica Set 보존·상태 조사 | 인프라 인증 검증 미완료; 팀원의 별도 인증 시험은 별도 표기 |
| Garage | 2노드 S3 객체 입출력·NiFi·Spark 검증 | 단일 노드 장애 시 쓰기 고가용성 보장 안 됨 |
| 모니터링 | 20대 메트릭, 대시보드·경고 규칙 배포 | 외부 알림 수신·전달 검증 미완료 |
| Django | 인프라 시험 앱 검증 | 팀 업무 애플리케이션 완성을 뜻하지 않음 |
| AWS | 인벤토리·절차·권한 조사 준비 | 이미지 생성·업로드·AMI·EC2 이전 미실행 |

## 작업 주체와 공개 범위

인프라 구축 및 운영 범위는 중앙 관리, 인프라 자동화, 승인된 설치·서비스 구성, 디스크 이전·MySQL 복제, 모니터링, S3 호환성 시험과 이전 준비다. 각 팀원이 관리한 VMware 호스트·기존 VM·추가 디스크 제공 및 팀 업무 코드까지 단독 구축 실적으로 기록하지 않는다. 기존 MongoDB와 Replica Set은 팀의 기존 자산이며 재설치·재초기화하지 않았다.

팀 파이프라인 담당자의 후속 검증은 [서비스·통합](02-services-and-integration.md)에서 별도로 인용한다. 테스트 통과, 시험 데이터 성공, 업무 E2E 완료를 서로 대체하지 않는다.

이 PR에는 Markdown만 포함한다. 작성자의 스크립트·Playbook·Role·원본 보고서·로그·VM 파일·비밀정보는 공개하지 않는다. 내부 주소는 논리 역할 또는 플레이스홀더로 표현한다. 근거 원본은 기존 보호된 위치에 보존하며 [근거 목록](07-evidence-and-handoff.md)에 식별자를 제공한다.

기존 [인프라 설계](../design/01-infrastructure.md)의 19대 구성은 설계 당시 기록이다. 이 문서의 20대 구성과 실제 Garage 구성은 후속 구축 결과이며, 기존 팀원 설계를 덮어쓰지 않는다.
