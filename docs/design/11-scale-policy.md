## 목적과 경계

생성 가구가 공간에 비해 지나치게 크거나 작아지는 일을 모두 검출한다. 명시적인 크기 요구가 없다면 원본 사진의 주변 물체에 대한 통상 치수 범위, 대상 가구의 품목·형태, 배치 깊이·원근·바닥/벽면 접점을 함께 사용해 시각적으로 적정한 투영 크기 범위를 추정한다. 이는 실제 치수 측정·설치 가능 판정이 아니다. 추정값을 products의 width_mm·depth_mm·height_mm 또는 실제 상품 검색의 필수 치수 조건으로 옮기지 않는다.

사용자가 명시한 치수·미니어처·대형 표현을 우선한다. 수치 요구가 있어도 원근 근거가 부족하면 사진상 투영 크기를 확정하지 않는다. 스케치 외곽은 위치·형태·대략적 점유 의도이며 실제 치수 또는 반드시 채워야 하는 크기가 아니다. 영역 크기만으로 대형·미니어처 의도를 확정하지 않는다.

## 생성 전 계획

1. 원본 사진과 입력 버전, 선택한 템플릿 버전을 고정한다. 배치 영역은 명시 좌표, 해석 좌표, 배치 문장 순서로 사용한다.
2. 원본 사진에서 기준 물체를 찾고 가능한 경우 여러 독립적인 기준을 비교한다. 기준 물체의 품목·영역·치수 축·통상 치수 하한/상한·깊이 관계·불확실성을 남긴다. 문·테이블을 공통 고정 치수로 가정하지 않으며 화분 등 편차가 큰 물체 하나로 크기를 확정하지 않는다.
3. 바닥/벽면·소실 방향·접점·배치 깊이를 고려해 대상 위치에서 비교한다. 서로 다른 깊이의 물체 픽셀 높이를 바로 비교하지 않는다. 선택 참조는 가구 세부 유형·구조·비례를 파악하는 자료이며 실제 치수나 방의 축척 근거가 아니다.
4. 원본 사진 가로·세로에 대한 가구 전체 외곽의 폭·높이 비율 범위를 각각 정한다. 하나의 정답값이나 전 품목 공통 비율을 사용하지 않는다. 하한과 상한을 모두 기록한다.
5. 근거 충돌·가림·깊이 불명·기준 부재는 신뢰도 LOW로 기록한다. 품목 사전 지식만 있는 CATEGORY_ONLY 또는 UNKNOWN은 공간 크기 확인으로 취급하지 않는다. 지원되지 않는 범위는 NULL이다.

생성 요청에는 고정 계획과 전처리 후 범위를 함께 전달한다. 원본을 자르거나 늘리지 않고 정사각 여백을 적용할 때 폭 비율은 원본 폭×scale_x/API 폭, 높이 비율은 원본 높이×scale_y/API 높이로 변환한다. 원본 범위·좌표를 덮어쓰지 않는다. 가구 비례·접점·배치 깊이·원본 카메라를 유지하며 스케치나 화면을 채우려고 과도하게 확대·축소하지 않도록 지시한다. 생성 모델이 지시를 반드시 준수한다고 보장하지 않는다.

## 생성 후 검증과 처리

원본·결과·선택 참조를 비교해 원근과 크기를 판정한다. 배경 구조·기준 물체·카메라/크롭이 바뀌었으면 변경된 배경을 새 크기 근거로 사용하지 않는다. 고정 계획과 결과 영역을 비교하되 배경 유지가 확인된 경우에만 같은 투영 좌표의 수치 비교를 적용한다.

| 크기 판정 | 의미와 처리 |
|---|---|
| APPROPRIATE | 근거·배경 유지·단일 대상 대응이 확인되고 하한·상한 안이며 원근 검사도 통과 |
| TOO_SMALL | 하나 이상의 축이 하한 미만이거나 원근 비교에서 과소 생성 판정 |
| TOO_LARGE | 하나 이상의 축이 상한 초과이거나 원근 비교에서 과대 생성 판정 |
| OUT_OF_RANGE | 한 축은 하한 미만이고 다른 축은 상한 초과하는 등 비례 범위 이탈 |
| UNCERTAIN | LOW 신뢰도·계획/검사 누락·배경 변화/불명·대상 없음/복수 등 판단 근거 부족 |

과대·과소·불확실은 NEEDS_SCALE_REVIEW로 표시하고 기본 추천 선택을 보류한다. 주석 검사·참조 구조 검사도 각각 통과해야 한다. 복수 검사 실패는 모두 표시하고 대표 상태 우선순위는 주석 → 구조 → 크기다. 생성 이미지와 이전 결과는 보존한다.

초기 정책은 자동 재생성 0회다. 비교 재시도는 동일 생성 이미지와 고정 계획으로 분석만 다시 호출한다. 수정 또는 같은 참조의 새 요청 준비 후 사용자가 명시적으로 생성하면 새 입력 버전·미리보기로 재생성한다. 지원하지 않는 범위나 실패를 무제한 API 반복으로 해소하지 않는다. 이후 자동 보정을 도입하려면 재시도 상한·비용·기존 결과 보존·품질 평가를 별도 확정한다.

## 저장·호출 계약

서비스는 기존 생성 실행·AI 분석 결과 및 jobs.input_refs_json의 불변 출력 참조와 checksum으로 계획/검사를 연결한다. 이번 정책은 신규 DB 컬럼·테이블을 추가하지 않는다. 정책 버전, 입력/원본/참조 checksum, 모델·분석 스키마·전처리 버전과 계획을 생성 실행에 고정한다. 실제 서비스 분석 유형·JSON 저장 배치는 통합 시 확정한다.

로컬 웹 MVP는 scene-context-scale-v4를 사용한다. 참조 구조 분석 후 scale 단계에서 Gemini를 한 번 추가 호출하며 원본 사진·선택 참조 두 장을 전달한다. scale.json은 불변 단계 출력이며 generation_request.json에 같은 scale_plan과 api_scale_bounds를 고정한다. 비교는 기존 3장 호출에 scale_check를 추가한다. 호출 응답·시도·latency·출력 checksum은 기존 단계 보존 방식을 따른다. 전용 깊이/카메라 보정 모델 또는 실측 엔진 구현을 뜻하지 않는다.

| JSON | 의미 |
|---|---|
| scale_plan.basis / confidence | EXPLICIT·CONTEXT·CATEGORY_ONLY·UNKNOWN / HIGH·MEDIUM·LOW |
| anchors[] | 원본 영역, dimension 축, typical_size_mm의 minimum/maximum, depth_relation, uncertainty. mm는 불확실한 통상값이며 실측/상품 규격 아님 |
| furniture_size_prior / placement_depth / contact_point / perspective_reason | 가구 유형·통상 크기 가정, 배치 깊이·접점·원근 근거 |
| explicit_size_intent | 사용자 명시 크기 요구 인용 또는 NULL |
| width_ratio / height_ratio | 원본 사진 기준 투영 폭/높이 비율의 minimum/maximum 또는 NULL |
| api_scale_bounds | 여백 사본 기준으로 변환한 폭/높이 비율 범위 |
| scale_check | status, room_geometry, findings, reason; 수치 비교 가능 시 observed_api_ratios·expected_api_bounds 추가 |

LOW 계획으로도 생성 예시는 제공할 수 있으나 공간 비례는 미확인으로 남고 추천 선택은 보류된다. 이전 버전 실행은 재작성하지 않는다. 새 생성 정책은 새 요청부터 적용하며, 이전 실행의 비교 재시도에는 고정 계획이 없으므로 크기 판정을 보류한다. CLI 및 일괄 임베딩에는 이번 웹 정책을 적용하지 않는다. 로컬 MVP의 다나와 참조 사용은 별도 시험 범위이며 서비스용 템플릿/상품 분리 원칙을 변경하지 않는다.

## 인수 기준

- 같은 가구가 서로 다른 깊이에 있을 때 화면상 크기만으로 과대·과소를 확정하지 않는지 확인한다.
- 정상·과대·과소·폭/높이 혼합 이탈을 모두 검사하고 각 축의 경계값을 포함한다.
- 가로형·세로형 원본의 정사각 여백 변환에서 하한·상한이 함께 변환되고 원본 계획이 보존되는지 확인한다.
- 기준 부재·후보 충돌·가림·낮은 신뢰도·배경/카메라 변화·대상 없음/복수·검사 누락은 정상으로 승격되지 않아야 한다.
- 미니어처/대형 의도와 명시 치수의 우선순위, 근거 없는 cm 값의 상품 규격 유입 차단을 확인한다.
- 구조·주석 검사가 통과해도 크기 실패면 선택을 보류하고, 비교 재시도에서 생성 API를 호출하지 않아야 한다.
- 계획 분석 실패 시 생성 전 중단하고 명시적 재시도에서 실패 단계만 다시 처리한다.
- 데모/모의 응답의 코드 검증과 실제 사진·모델의 시각 품질 평가를 구분한다. 품목·유형·배치 깊이별 사람이 판정한 정상/과대/과소 표본으로 오탐·미탐·판단 보류율을 측정한 뒤 통상값과 허용 범위를 조정한다.
