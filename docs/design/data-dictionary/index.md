# 데이터 속성 사전 안내

데이터 모델의 컬럼명을 클릭하면 해당 속성의 저장 의미·형식 후보·예시·참조 대상과 주의점으로 이동한다. 이 사전은 컬럼을 추가한 구현 명세가 아니라 현재 논리 모델을 이해하기 위한 설명이다.

## 직접 추천 현행 계약

2026-10-15: 먼저 [직접 추천 속성·타입·FK 변경안](09-direct-recommendation.md)을 읽고 공통 상품/원천/이벤트 필드를 함께 확인한다. 신규 입력→맥락→추천 관계가 우선이며 생성물/템플릿 필수 FK는 새 흐름에 적용하지 않는다. 기존 데이터/파일을 삭제하거나 ORM/DDL이 이미 변경된 것으로 간주하지 않는다. 실험 특징·미래 행동 라벨·상품 실측/AI 추정을 분리한다.

## 헷갈리기 쉬운 구분

| 속성 | 저장 의미 |
|---|---|
| id | MySQL 행의 UUID4 기본키. API와 메시지에도 같은 UUID 사용 |
| product_key | Delta와 MySQL 재처리에서 같은 상품을 찾는 안정적인 키 |
| offer_key | 판매처·상품·옵션 단위의 판매 항목 키 |
| raw_document_id | MongoDB 원천을 찾는 문자열 참조, MySQL FK가 아님 |
| event_id | 동일 이벤트 재전송을 식별하는 키 |
| impression_id | 어떤 실제 노출에 대한 반응인지 연결하는 UUID |
| index_version_id | 추천에 사용한 검색 파일과 UUID 매핑 버전 |

| collected_at | 제공처 정보 수집 시각 |
| occurred_at와 received_at | 사용자 행동 발생 시각과 서버 수신 시각 |

## 공통 속성

### common id

프로젝트의 MySQL 행 한 건을 식별하는 UUID4 기본키다. 신규 행 생성 시 한 번 발급하고 재처리·이관에서 보존한다. Django UUIDField는 MySQL CHAR(32)에 저장하며 참조 FK도 같은 타입이다. API와 메시지에는 같은 값을 하이픈을 포함한 UUID 문자열로 전달한다. assets·projects·jobs의 public_id는 제거하고 id로 통일한다. MongoDB _id는 ObjectId로 별도 관리한다. 세부 생성·중복 처리 규칙은 [데이터 모델](../03-data-model.md#uuid-생성과-보존-규칙)을 따른다.

### common created_at

DB 행을 처음 등록한 UTC 시각이다. 데이터가 수집되거나 사용자가 행동한 시점과 다를 수 있다. 예시는 2026-10-12T01:00:00Z다.

### common updated_at

DB 행을 마지막으로 수정한 UTC 시각이다. 원천의 가격 최신성을 뜻하지 않는다. 불변 이력에는 필요 여부를 따로 정한다.

### common raw_document_id

MongoDB raw_products._id를 문자열로 기록한 원천 추적 값이다. DB 간 FK가 아니며 수집 원천을 조회할 수 있는지 처리 코드가 확인한다.

## 필드가 많은 이유와 구현 범위

상품과 사용자 핵심 흐름, 재처리와 추적, 검수와 기록 이관의 요구를 함께 표현해서 속성이 많다. 검수 보조 기능·상세 분석·자동 lease 회수 등은 단계적으로 구현하되, BRD의 원천 보존·구매 정보 일치·실패 재처리·기록 이관 요구는 남긴다. 속성이나 엔터티를 삭제하기 전 관련 요구사항과 기존 관계를 함께 검토한다.

형식과 예시는 제안이며 NULL 허용·정확한 길이·상태 코드·JSON 스키마·삭제 정책은 DDL 전에 확정한다. users는 UUID PK를 선언한 Django 커스텀 인증 모델의 대표 필드만 설명한다. 복합 고유키는 전체 ERD와 데이터 모델의 인덱스 표에서 확인한다.

컬럼을 변경하면 데이터 모델·ERD·이 사전을 함께 수정한다. 서버 대수나 AI API 방식은 이 사전 추가로 바뀌지 않는다.


## 그림과 필드 설명의 연결

업무별 ERD는 핵심 관계를 먼저 보여주고 전체 필드는 접힌 표로 제공한다. 생략된 공통 FK·업무 간 관계는 전체 관계 목록에서 확인한다. 이 사전의 필드는 그림의 표시 여부와 관계없이 유지한다. placements는 이전 배치안 참고이며 신규 생성·추천 흐름에서는 사용하지 않는다.
